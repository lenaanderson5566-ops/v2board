# 账户状态与快速开始

## 账户状态

`GET /api/v10/me` 的 `data.accountStatus.state` 决定用户端的主导航。服务端按表中顺序匹配，以服务器当前时间判断到期。这里的 `new` 描述当前权益，不能据此判断注册时间或购买历史。[状态判定](../app/Services/AccountStatusService.php) · [用户导航](../frontend/src/user/user-navigation.ts)

| 优先级 | 条件 | 状态 | 界面入口 |
| --- | --- | --- | --- |
| 1 | 账户已封禁 | `banned` | 隐藏常规导航。新登录被拒绝时展示封禁说明。 |
| 2 | 独立额度包余量 `credit_balance > 0`，包括没有周期套餐或周期套餐已到期的账户 | `active` | 使用情况、连接与下载、账单、帮助中心 |
| 3 | 没有独立额度余量，也没有 `plan_id` | `new` | 总览、购买订阅、账单、帮助中心 |
| 4 | 没有独立额度余量，有周期套餐，且 `expired_at` 小于或等于当前时间 | `expired` | 总览、续订套餐、账单、帮助中心。总览可查看原套餐及到期时间。 |
| 5 | 有周期套餐，且 `expired_at` 为空或在未来 | `active` | 使用情况、连接与下载、账单、帮助中心 |

周期套餐的已用流量达到配额时，账户在有效期内仍为 `active`。没有独立额度余量时，配置页提示流量耗尽并提供“管理订阅”。配额为零且没有独立额度时，页面提示服务暂不可用。下载配置要求账户未封禁、未删除，且有独立额度余量，或有仍在有效期内的周期流量余量。[服务可用性与配置下载](../app/Services/UserService.php) · [配置页](../frontend/src/user/SubscribePage.tsx)

普通登录默认进入总览或使用情况。新注册且状态为 `new` 的账户直接进入套餐选择，已获有效试用的账户进入使用情况。用户从购买或客户端授权流程登录时，优先返回原来的目的地。已登录且页面可见时每 60 秒复查状态，到期时也会重新获取。封禁账户使用已有凭据访问 V10 用户接口会收到 HTTP 403。[账户导航](account-experience.md#account-navigation) · [状态刷新](../frontend/src/user/UserStatusGate.tsx) · [V10 账户鉴权](../app/Http/Controllers/V10/ResourceController.php)

## 快速开始与账单

“连接与下载”位于 `#/subscribe`。有可用订阅的用户可以确认设备系统，选择客户端并导入，然后按指引开始使用。系统支持手动切换 Windows、macOS、Android、iOS 和 Linux。所选客户端决定配置格式，可用操作包括一键打开、复制订阅链接和扫码。“获取客户端”提供对应平台的官方下载或已配置的镜像，“可用节点”按钮跳转到本页的节点列表。订阅链接和二维码包含访问凭据，泄露时可在账户安全中重置。[订阅导入](../frontend/src/user/SubscriptionImport.tsx) · [客户端下载与镜像](client-mirrors.md) · [账户安全](authentication-security.md)

“账单”位于 `#/order`，可查看待支付、开通中、已取消、已完成和已折抵订单的金额与详情。待支付订单可继续结算，开通中的订单可查看处理进度。总览也会向尚未开通服务的用户提示已有待处理订单。[账单与待支付订单](account-experience.md#account-navigation)

“使用情况”支持切换近 7 天和近 30 天，均包含今天。上传和下载按记录所属统计日汇总，可跨月、跨年，与套餐计费和重置周期独立。外部接口 `GET /api/v10/me/traffic-records` 只返回当前用户的已保存记录，可传 `days=7` 或 `days=30`，省略时取当月。[流量查询](../app/Services/Actions/User/StatActions.php) · [统计日归属](../frontend/src/user/usage-data.ts)

## 账户删除

自助删除要求近期安全登录、当前密码及明确确认；管理员、余额或佣金未处理、订单处理中、佣金待结算、工单未关闭时拒绝。清理在同一数据库事务中完成：账号身份匿名化，清除安全凭据、绑定与个人资料，解除套餐和用户组，替换订阅 token 与节点 UUID，并将独立流量批次及流量重置次数的剩余权益归零。权益发放记录、订单及必要账务和安全记录保留；清理失败时回滚，不形成只清除部分资料或权益的状态。

删除标记与 MFA 版本共同阻止旧会话，即使旧缓存元数据重新出现也不能认证；浏览器 Cookie、原生 Bearer 和删除前签发的登录授权码均失效。原订阅链接及已缓存的一次性、动态订阅链接不能继续获取配置。节点用户查询排除删除账号；已经连接的客户端依赖节点下一次同步撤销，后台接口回归不代表真实节点连接已即时断开。`auth-security` 验证资料、权益、回滚、Cookie 删除请求、订阅拒绝和其他账号隔离，配合 `browser-session`、`session-authorization` 与 `node-backends` 回归。

后台单个和批量删除复用 `EraseAccountData` 清理凭据、绑定、个人关联资料及剩余权益，并沿用后台原有的用户与所属订单硬删除行为。批量操作在事务中锁定并固定目标 ID，再校验确认人数；清理时邀请关系等字段变化不改变删除范围。单个清理或批量中任一账号失败会回滚数据库变更；已经撤销的缓存会话可能需要重新登录。携带用户 ID 的旧邮件任务在账号已不存在时跳过。`admin-user-identity` 通过真实后台路由覆盖单个和批量删除、权限、人数变化、关系筛选、故障回滚、旧凭据与订阅拒绝、队列邮件及其他账号隔离。
