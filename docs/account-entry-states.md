# 账户进入界面与 Laravel 状态规则

状态在 `AccountStatusService::forUser()` 中由 Laravel 计算，通过 `GET /api/v10/me` 的 `data.accountStatus` 返回，前端解码为内部 `account_status`；`user/info` 是内部兼容映射名称，不是仍开放的旧用户 URL。前端不按注册时间或浏览器时间猜测状态。

| 优先级 | 状态 | 后端判定 | 默认进入后的内容 |
| --- | --- | --- | --- |
| 1 | banned | `banned` 为真 | 封禁说明；已有会话可展开工单中心并退出，没有购买或导入入口。新登录仍被拒绝，返回 `ACCOUNT_BANNED` 错误码以展示专用界面。 |
| 2 | new | 没有 `plan_id` | 套餐选择、配置步骤、使用文档与工单支持，不显示可用订阅或导入按钮。此状态准确含义是“未配置套餐”，不是按账户年龄判断新注册。 |
| 3 | expired | 有 `plan_id`，且 `expired_at` 非 null、`<= time()` | 到期说明、原套餐及到期时间、续订／选择套餐、订单记录及文档，不显示导入按钮。 |
| 4 | active | 有 `plan_id`，且 `expired_at` 为 null 或在未来 | 有效订阅总览：套餐、真实剩余额度、导入和使用分析。 |

注册开启赠送试用时，`AuthActions::register()` 会直接赋予套餐和未来到期时间，因此进入 active。长期套餐的 null 到期时间同样进入 active。新注册未获套餐时进入 new，不因接口仍返回订阅 URL 而显示可用配置。

`is_available` 复用现有 `UserService::isAvailable()`，要求未封禁、有额度且有效期在未来或为 null；不改动现有授权策略。`quota_exhausted` 单独表示有效期内 `u + d >= transfer_enable` 且总额大于零，与节点下发查询的剩余额度要求一致。这类用户仍显示“订阅有效”，但提示额度已用尽并隐藏导入；零额度配置也提示核查套餐。不会将额度耗尽误写为到期。

`UserService::getAvailableUsers()` 的批量查询在边界使用 `>= time()`，客户端可用性判断则使用 `> time()`；界面采用后者，准确到期秒归为 expired。无套餐但管理员手动赋额的特殊账户仍归入未配置套餐入口，不宣称存在有效套餐。

登录／注册后原有跳转总览行为保留，由账户状态选择入口；未封禁用户仍可直接访问账户、订单、文档等已有路由。已有会话每 60 秒在可见页面复查状态，窗口重新聚焦、数据提交及到期计时触发刷新。此展示限制不能替代 Laravel 接口授权，也没有放宽封禁登录或服务可用性规则。

本轮同步补齐 `user/info` 的 `u`、`d` 字段：此前总览读取这两个字段，但接口没有提供，会误显示零使用量。订阅余量现在据实际计数计算。

## 账户删除

自助删除要求近期安全登录、当前密码及明确确认；管理员、余额或佣金未处理、订单处理中、佣金待结算、工单未关闭时拒绝。清理在同一数据库事务中完成：账号身份匿名化，清除安全凭据、绑定与个人资料，解除套餐和用户组，替换订阅 token 与节点 UUID，并将独立流量批次及流量重置次数的剩余权益归零。权益发放记录、订单及必要账务和安全记录保留；清理失败时回滚，不形成只清除部分资料或权益的状态。

删除标记与 MFA 版本共同阻止旧会话，即使旧缓存元数据重新出现也不能认证；浏览器 Cookie、原生 Bearer 和删除前签发的登录授权码均失效。原订阅链接及已缓存的一次性、动态订阅链接不能继续获取配置。节点用户查询排除删除账号；已经连接的客户端依赖节点下一次同步撤销，后台接口回归不代表真实节点连接已即时断开。`auth-security` 验证资料、权益、回滚、Cookie 删除请求、订阅拒绝和其他账号隔离，配合 `browser-session`、`session-authorization` 与 `node-backends` 回归。
