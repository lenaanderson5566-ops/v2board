# 后台组件与视觉规范

后台使用 React、TypeScript、Lucide 和应用自有 CSS。交互复杂的基础组件逐步采用 Radix Primitives，目前账户菜单、订阅管理标签页及优惠券标签页已接入。保留业务组件和既有 API 契约，不引入 Ant Design。

## 组件边界

- Radix 管理菜单与标签页的语义、键盘操作、焦点恢复和弹层碰撞处理。菜单通过 Portal 放到页面根节点，避免容器遮挡。
- 普通按钮、原生输入框和业务布局继续使用现有 HTML 与 CSS。引入第三方组件解决交互问题，不为简单元素额外加封装。
- `admin-section.tsx` 统一业务页标题与操作提示；提示区区分成功与错误，并提供对应的读屏语义。
- `admin-operation.ts` 共享异步操作状态，并通过同步锁阻止按钮禁用前的快速重复提交。失败保留表单草稿，提交时锁定编辑。
- `billing-price-input.ts` 严格把美元十进制文本转成整数分，保留空白与零的区别，拒绝额外小数、科学计数及溢出；服务端继续独立校验。

## 样式维护

后台颜色、间距、控件高度和圆角集中在 `admin.css` 的 `body[data-console="admin"]` 变量内；`admin-controls.css` 负责标签与筛选，`admin-surfaces.css` 负责卡片、表格和弹层的共用布局。样式仅作用于后台，不更改用户端。

| 元素 | 统一规则 |
| --- | --- |
| 页面与卡片 | 卡片圆角 8px，标准内边距 16px；窄屏 12px。标题区和正文沿同一对齐线，保留菜单可见溢出。 |
| 输入与按钮 | 标准高度 36px，窄屏 40px，控件圆角 6px；行内操作保留紧凑尺寸。复选框/单选框使用独立 16px 尺寸，不能继承文本输入高度。 |
| 筛选与标签 | 复用 AdminFilterBar、AdminTabs、AdminChoiceGroup；日志仅增加日期和关键词所需宽度，不重复定义整套筛选样式。 |
| 表单 | 统一字段标签、说明和分组间距。带单位输入框与其容器伸展，不能在窄屏收缩为短输入框；业务字段列数与校验保留。 |
| 弹窗与抽屉 | 普通弹窗最大 600px，普通抽屉 560px，宽窗口最大 960px；窄屏抽屉全宽。标题固定、长标题换行、关闭按钮保持固定尺寸；内容可独立滚动。 |
| 操作区 | Editor 复用 form-bottom；自定义弹层复用 admin-dialog-form / admin-dialog-actions，提交按钮靠末端，窄屏可换行。危险动作保留原确认和强调。 |
| 状态 | 中性说明与失败/待处理状态区分。Lightsail 失败卡片使用警示底色，保留完整动作、错误码及恢复入口。 |

新增布局优先复用 `.panel`、`.panel-head`、`.section-tabs` 和现有表单结构，避免内联样式及堆叠同一选择器的覆盖规则。移动端导航限定宽度，表格横向滚动限定在表格容器，页面本身不应横向溢出。减少动画偏好关闭侧栏过渡。

## 页面与子界面覆盖范围

按侧栏检查全部入口，并按工作区检查支付、客户端、站点、通知、套餐、工单、邀请、节点、服务器、黑名单和访问日志的标签子页。仪表盘、营销与内容、字典和采集保留使用已有组件；业务专用图表、编辑器和部署步骤保留其结构。

弹窗重点核对：Lightsail 配置与嵌套密钥、Cloudflare 凭据、路由编辑、维护操作和日志策略设置。页面及子页复用同一控件、标题、留白与操作区规则；不为每个页面再创建独立主题。

## 新增、编辑与详情弹窗交互

需要草稿保护的窗口显式启用 `Modal.guardChanges`，复用表单的 `data-unsaved`、`aria-busy` 或 `data-saving` 状态。标题关闭、Escape、遮罩和 Editor 的取消入口使用同一关闭检查：提交中保留窗口，有未保存修改时确认放弃。业务自行提供关闭保护的节点、路由、字典和复核表单保留其专用检查，避免重复确认；成功保存可以直接结束编辑。

Banner 上传和保存期间锁定全部字段及关闭操作，失败保留草稿；长表单固定操作区。其网格列和语言分组必须允许缩小，避免窄屏出现横向裁切。支付设置保存时锁定网关、分类与图标；切换网关或填入风控建议前确认可能丢失的字段修改。排序、公告、风险复核及服务器额度使用同步提交锁，失败后允许重试；额度表单提交中不能取消或修改，取消草稿需确认。

焦点循环只纳入可见、可用且可 Tab 到达的控件，排除隐藏输入、隐藏祖先、禁用 fieldset 和 tabindex=-1。嵌套窗口仍只关闭最上层，并在关闭后恢复触发按钮焦点。详情中长标识、邮箱和证据文本允许换行，表格滚动保留在自己的容器内。

## 后续组件迁移

先覆盖易出现键盘和遮挡问题的交互，再按页面迁移弹窗、确认框和组合选择器。共享弹窗目前还被用户前端使用，迁移前须单独覆盖关闭行为、焦点恢复、嵌套弹层和表单提交测试。

复杂表格可评估 TanStack Table，需保留服务端分页、筛选及排序契约。shadcn/ui 的默认安装需要 Tailwind，当前项目已有 CSS 体系，暂不增加第二套样式系统。
