# 管理后台运行诊断

节点列表增加运行状态和状态筛选，支持打开「运行状态」诊断。状态依据配置/用户拉取、能力上报和流量上报时间计算，最近通信超过 5 分钟显示离线；缓存过期或没有记录时显示「暂无通信记录」。在线且服务器额度超限显示「额度受限」。隐藏节点不等同于节点进程离线。

配置请求记录仅保存配置哈希、提供时间和接口版本，保留 24 小时，不保存配置正文、证书或密钥。管理员点击诊断时才重新生成该节点配置并比较哈希，避免在整个节点列表中逐条生成配置。比较包含当前路由和面板同步间隔，可识别这些设置变更。

- 无记录：暂无配置拉取记录。
- 哈希不同：配置已变更，等待节点拉取。
- 哈希相同：已提供最新配置，待应用确认。
- 无法生成配置：配置生成异常。

成功响应或 304 都不能证明代理核心应用成功。当前 V2Node 和 V2Box 未提供配置应用回执，因此应用状态始终 `unconfirmed`，不能声称已生效。V2Box 的核心版本来自现有能力上报，并显示上报时间；V2Node 没有上报时显示「尚未上报」。子节点诊断使用父节点运行配置及通信数据。

系统监控增加只读健康检查，分别检查数据库连接、Redis、缓存读取、定时任务执行心跳、Horizon 主进程与未执行迁移。失败输出固定提示，不输出异常正文、连接字符串或服务器路径。检查不写业务数据、不执行迁移、不重启进程。Horizon 正常不代表每个任务成功；缓存检查只验证读取，不证明写入能力。

定时任务心跳从加载任务定义时写入改为每分钟任务实际执行时写入，避免 `route:list` 等仅加载调度定义的操作产生虚假心跳。升级后应确保 `schedule:work` 使用新代码；旧常驻进程需要按现有部署流程重启。

新增管理员 GET 接口（沿用 admin/log 中间件）：
- `/api/v1/{adminPath}/server/manage/runtime?type=v2node|v2box&id=123`，60 次/分钟。
- `/api/v1/{adminPath}/system/health`，20 次/分钟。

不改变节点配置响应正文或 ETag，不增加用户 API，不要求节点升级；没有应用回执的限制在界面明确提示。

验证：`php tests/admin-diagnostics.php`（仅 local）；节点 V10、框架启动及路由权限回归；前端诊断和节点管理测试；生产构建。
