# 原后台对照

打开 `admin-parity.html`，可以搜索模块、字段和操作，并筛选缺失或部分迁移项。`admin-parity.json` 提供相同的机器可读清单。

重新生成：在 `frontend` 目录执行 `npm run audit:admin`。基准为仓库保留的原后台构建文件 `public/assets/admin/res_005.js`，报告标明其最后修改提交及每项来源行号。

本次提取全部 16 个原菜单、80 个设置字段、19 个用户编辑字段，并抽查关键操作入口。浏览器只读检查原仪表盘、站点设置、邮件设置、用户列表与用户编辑抽屉；没有发送邮件或调用外部 Webhook。动态节点、支付网关和旧扩展还需逐页行为回归。报告中的“已保留”表示字段或接口入口存在，不能视为完整功能验收。

本次补齐已用上传、已用下载、返利类型、邀请人邮箱。GB 在提交时转换为整数字节；用户编辑加载详情，避免遗漏邀请人。后端修复未提交邀请人字段时意外解除邀请关系的问题。验证：前端构建成功、59 项单元测试通过、50 项后端冒烟检查通过。测试记录在数据库事务内回滚。

主题选择等模板配置按既定要求移除，自定义页脚 HTML 保留。剩余差异已列在报告中，包括金额输入单位、排序、CSV、筛选与批量操作、订单和队列入口等；这份报告不宣称两套后台完全等价。

用户管理按钮的后续核对与修复详见 [user-buttons-review.md](user-buttons-review.md)。高级筛选、CSV、邮件、批量操作、分配订单及个人记录入口已补齐，当前生成报告包含这些实现；历史测试数量为当时记录。
