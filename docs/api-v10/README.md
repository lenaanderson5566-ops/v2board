# FastDog V10 user API

The new user API is `/api/v10`. Administration, operations/risk and node communication retain their existing APIs. The unfinished `/api/v1/staff/*` API has been retired and is not migrated to V10. Staff retirement removes the legacy `is_staff` column through the approved upgrade migration; fresh installations omit it. Follow [the upgrade procedure](../update-script.md) for schema changes; staff retirement itself does not change the framework requirement. Current installations require PHP 8.4+ and the committed Laravel 13 dependencies.

## Contracts and compatibility

- [OpenAPI](openapi.json) describes all explicitly registered resources, inputs, outputs, permissions and native responses. [Mapping](mapping.md) lists every migrated legacy function. `endpoints.json` is the routing inventory; `contracts.json` declares field projections.
- [Retained endpoints](retained-endpoints.md) lists legacy non-management routes and their V10 equivalents; [route audit](audit.md) records checks, findings and verification limits.
- Legacy user business and public-content routes have been retired with explicit authorization. Only the routes in `retained-legacy.json`, administrative/risk APIs, node communication, configured subscription paths and historical webhook URLs remain available. Staff routes are retired. Both controller sets invoke shared business actions in `app/Services/Actions`; no HTTP forwarding or dynamic controller dispatch is used.
- User browsers and the administrative console use separate scoped HttpOnly cookies, `X-Browser-Client`, and in-memory CSRF tokens. Mutations require an exact allowed Origin and `X-CSRF-Token`; the frontend sends `credentials: include`. Native clients retain `Authorization: Bearer <session token>`. Old localStorage tokens are read only for the bounded migration exchange, not for normal requests. Query credentials cannot authenticate browser requests. Subscription credentials remain in their dedicated subscription path.
- JSON successes use `{data, meta?}`. Amounts are integer minor currency units with `currency`, traffic uses bytes and dates use UTC ISO 8601. `null` prices mean unavailable; zero prices remain zero. Order, billing-period, ticket-priority and ticket-status enums are stable strings.
- Pagination uses `page` and `pageSize` (default 20, maximum 100), returned in `meta.pagination`. Creation uses 201, queued mail uses 202 and a task identifier, and no-content actions use 204.
- Errors use `application/problem+json`: `type`, `title`, `status`, `detail`, `code`, `requestId`, and field `errors`. Statuses distinguish unauthenticated (401), forbidden (403), conflict (409), validation (422) and throttling (429). Internal traces and paths are never sent.
- Language negotiation uses `Accept-Language`, including quality weights, and responses declare `Content-Language`. Request IDs are generated by the server. Logs include route templates, method, status and duration; they exclude payloads, URLs with tokens, passwords, codes and account credentials.
- The frontend central transport maps existing component view models to explicitly declared V10 wire types. User traffic uses V10; administrative traffic retains its existing contract. Unknown user operations fail locally instead of falling back to old APIs. `frontend/src/shared/v10-types.ts` publishes resource and input types.

## Native protocol exceptions

`GET /subscriptions/{subscriptionToken}` returns native client configuration, without an API envelope. Supported canonical `format` values are defined by `getSubscriptionsSubscriptionTokenInput` in the published OpenAPI (including `mihomo`, `clash-verge`, `flclash` and `sing-box`). An omitted format uses recognized client detection. `general`/`uri`, retired aliases and `flag` are not public fallbacks; unknown or disabled clients are rejected, and explicit formats must match the client family. Default user links use V10; administrator-defined subscription paths retain their original form. Existing custom links return configuration directly; the old default `/api/v1/client/subscribe` is retired. Default links generated from any context (including administration) use V10.

Subscription language precedence is an explicit `language` parameter, a supported `Accept-Language` preference, the account's saved language, then the application default. Missing or unsupported language headers must not override the saved preference. Permanent, one-use and time-based subscription credentials retain their existing validation behavior.

Payment callbacks use `/webhooks/payments/{provider}/{endpointId}`, accepting provider-required GET/POST and their native payload/signature/response. New payment requests and administrative callback displays use V10 addresses, including custom callback domains. Old callbacks remain compatible for previously created payments; both paths use the same business handler and idempotent order provisioning. Telegram uses `/webhooks/telegram` and validates `X-Telegram-Bot-Api-Secret-Token`; the old signed query entry remains compatible. Banner images and other binary/provider responses are not wrapped. Administrative CSV retains its existing API. Published installer downloads use `GET /api/v10/public/client-installers/{installerId}/content`, including HEAD and byte-range support. The old `/client-mirrors/{id}` route returns 404. Existing Banner image URLs are normalized to V10 when read.

`POST /me/invitations/retired-codes` is removed (404); the former 410-only compatibility handler is no longer registered. Email invitations are the supported replacement. The obsolete `/public/page-views` invitation counter is retired (404); historical invitation records remain available for upgrade compatibility and account deletion cleanup. Account responses no longer include the unused third-party `avatarUrl` email fingerprint.

## Maintenance and validation

The editable contract source is the `api/v10/` module tree. `openapi.json` is its manifest (global OpenAPI metadata, ordered `x-modules` entries and legacy/node inventory order), not the file to import into OpenAPI tools. Each `modules/*.json` file owns complete path items and named components; the generator merges them into the complete single-file `docs/api-v10/openapi.json`, with only internal `#/components/...` references and no external file dependencies. Modules contain standard OpenAPI schemas plus internal `x-runtime-resource` / `x-runtime-field` projection metadata, operation `x-runtime` mappings, browser aliases and legacy/node inventory metadata. `api/v10/mapping-notes.md` owns only the explanatory mapping prose. Published OpenAPI omits those internal annotations.

From the project root, using Python 3 (no third-party packages):

```sh
python scripts/generate-v10.py
python scripts/generate-v10.py --check
python -m unittest discover -s scripts -p test_generate_v10.py
```

On systems where Python is named `python3`, use that command instead. The generator writes exactly seven publications: `docs/api-v10/{openapi,contracts,endpoints,node-api}.json`, `docs/api-v10/mapping.md`, and `frontend/src/shared/v10-{contracts.json,types.ts}`. Commit source and generated changes together. `--check` is read-only and exits nonzero on drift, including missing files. Duplicate JSON keys, module entries, paths, component names, operation IDs/browser aliases, unlisted modules, paths outside the module directory, incomplete inventory ordering, and unresolved/external references fail generation before any publication is written. The former competing document generators are removed.

Module ownership:

| Module | Owned contract area |
|---|---|
| `common.json` | Security schemes, Problem/Pagination/scalar/task schemas, shared responses, headers and parameters |
| `authentication.json` | Registration, sign-in, sessions, passwords, MFA |
| `account.json` | Account profile/settings, banners, usage resets, download accounts and traffic history |
| `subscriptions.json` | Subscription delivery and lifecycle |
| `commerce.json` | Plans, orders, payments, credit packages, gift cards and coupons |
| `referrals.json` | Invitations, referral accounting and commission withdrawals |
| `support.json` | Tickets, notifications, announcements and knowledge articles |
| `integrations.json` | Telegram and mail webhooks, binding and unsubscribe |
| `clients.json` | Client releases/configuration/authorization, node previews and diagnostics |
| `nodes.json` | Machine-to-machine node communication |
| `analytics.json` | Public analytics configuration and events |

Edit an existing module for an endpoint change. Put an entire path item (all methods) in one module and reference shared components by their existing names. Component names are global across modules. For a new business domain, create one module with `paths` and `components`, then add it to `x-modules`; every module JSON must be listed once. Preserve `x-legacy-order` and `x-node-order` when adding inventory entries. Never edit the seven publications directly.

Common definitions are reused only where the complete definition is identical: differing native responses, error descriptions, required flags, security and cache policies remain distinct. Schema references and exported TypeScript names remain stable. The historical `node-api.json` export expands shared responses/headers/parameters, so its consumers keep the same shape. The backend and browser still load their generated runtime contracts; Python and module assembly are development-only and are not required by installation, upgrade or request handling.

The Python regression suite uses only the standard library and temporary directories. It covers deterministic publication, read-only drift detection, module omissions/duplicates, duplicate definitions and operations/aliases, unresolved/external references, inventory ordering, no-store headers and node export compatibility. `tests/api-v10-inventory.php` also checks module projections against runtime contracts and the actual Laravel router. Restricted environments can set `TMPDIR` to a writable temporary directory before running the Python suite.


PHP routes, controllers, validation and resource behavior remain handwritten; generation never rewrites application code. When behavior changes, edit implementation and canonical contract together, generate, then run `api-v10-inventory`, `api-v10`, `api-route-audit` and relevant business suites through `tests/run.php` **in a disposable workspace and temporary databases** as described in [test organization](../test-organization.md). Frontend validation uses `npm test -- --run` and `npm run build` from `frontend`.

The generated PHP runtime contract is still loaded from `docs/api-v10/contracts.json`. Installation and `update.sh` consume committed outputs and do not require Python or regenerate contracts. Provider and mail tests use fake transports; actual provider signing and delivery require deployment verification.

## Deployment and rollback

Deploy backend changes and the tracked `public/console` frontend build together. Preserve the previous commit and build outside the public document root; the existing `update.sh` site backup includes the frontend build. Clear configuration, route and compiled-view caches, then terminate Horizon gracefully so the existing supervisor restarts workers with the updated actions. Existing node entry points and database structures are unchanged.

If rollback is needed, restore the matching previous backend commit and frontend assets from the site backup, clear caches and restart workers. Do not mix an old backend with the V10 frontend build. This release removes legacy user business/public endpoints; deploy the matching frontend build at the same time. The declared compatibility allowlist remains available.

## Currency contract (CNY and USD)
Amounts are integer minor units in the accompanying currency (fen for CNY, cents for USD). Existing accounts, prices and historical assets remain CNY; upgrades do not exchange balances or rewrite historical order amounts. New accounts inherit `new_user_currency` once (default CNY, configurable as USD); account currency is immutable and denominates balances, commissions and new orders. USD plan prices are independently configured; null means unavailable and zero remains a valid price. Language changes formatting, not currency.

Payment quotes distinguish order currency from channel payment currency. Verified cross-currency settlement is enabled for EPay, Paytaro, PaytaroQR and StripeCheckout; USD collection is limited to StripeCheckout. Cross-currency initiation requires confirmation of `expectedPaymentAmount` and `expectedPaymentCurrency`; changed quotes return 409. Per-order/channel snapshots preserve amounts, fees and rates for callback verification. Payment asset/network labels are presentation metadata, not account currency. See [billing and currencies](../billing-currencies-coupons.md) for configuration and historical limitations.

Use the full approved `update.sh` flow for billing migrations before reopening the site. Legacy global `currency`/`currency_symbol` settings remain CNY-only compatibility fields; this does not restrict `new_user_currency` or per-account/order currency to CNY. Do not use the global display symbol to label USD amounts. Historical CNY deposit bonuses and amount gift cards do not automatically apply to USD accounts.

## fastai session configuration

`GET /api/v10/me/client-config?clientVersion=0.8.99&platform=windows` (also HEAD) requires an authenticated user session (native clients send Bearer; browser-mode requests use the scoped Cookie session). Supported platforms are windows, android, macos, linux and ios. It returns native `application/yaml`, with `Cache-Control: private, no-store`, directly from the shared FlClash/Mihomo configuration generator. It does not use subscription tokens, custom subscription domains or redirects.

Missing/revoked sessions return 401; banned users return 403; no usable subscription returns 403 `SUBSCRIPTION_UNAVAILABLE`; disabled FlClash strategy returns 403 `CLIENT_DISABLED`; the current minimum-version policy returns 409 `CLIENT_VERSION_TOO_LOW`. Version checks use the validated clientVersion field, not a fabricated FlClash User-Agent. Configuration errors use application/problem+json and requestId. Entitlement errors do not revoke sessions. Existing token/custom subscriptions keep their native behavior.

Deploy the backend before distributing the updated fastai client. Clear/rebuild cached routes using the normal deployment workflow. There is no fallback to a shareable subscription URL. Validate locally with `php tests/fastai-client-config.php`, V10 contract/inventory tests and subscription compatibility tests.

Configuration requests are recorded as `Client configuration request` in the API log: userId, clientVersion, platform, requestId, method, status, outcome, code and durationMs. Existing subscription risk logs also record configuration-generation success and denial reasons. Request credentials, query tokens and configuration bodies are excluded from database API logs.

## FastAI browser sign-in

Deploy the V10 backend and rebuilt user frontend before distributing the new client.
`v2board.app_url` must be the canonical HTTPS website origin. No database migration
is required; the existing shared cache must support atomic locks (Redis is recommended).
After deployment, rebuild the frontend with `npm ci && npm run build`, clear stale route
and configuration caches using the existing deployment procedure, and restart long-lived
PHP workers. Do not log authorization request IDs, codes, verifiers or callback URLs.

- `POST /auth/client-authorizations`: create a five-minute request with S256 PKCE,
  random state, platform and a strictly validated redirect URI.
- `GET /me/client-authorizations/{authorizationId}`: view the request using the
  browser's scoped Cookie session; this does not grant access.
- `POST /me/client-authorizations/{authorizationId}/approval`: explicit user consent,
  returning a one-minute, single-use code through the dedicated callback.
- `POST /auth/client-session-exchanges`: exchange the code with its original verifier
  and redirect URI. The resulting App session is independently revocable. An expired,
  banned or revoked browser session cannot authorize a new App session.

Windows, macOS and Linux use `http://127.0.0.1:{ephemeralPort}/fastai-auth/callback`
(ports 1024–65535). Android uses only `ws.fastdog.fastai://oauth/callback`; S256 PKCE
protects intercepted codes. Import/deep-link subscription handlers remain disabled.
Normal launches restore the encrypted App session and validate it against the backend;
only missing, expired or revoked sessions require signing in again. Email/password login
remains available. iOS sign-in integration is outside this client's supported targets.


### Shared one-time session authorization

App-to-browser login links and browser-to-App PKCE approval share the same authorization-code service. Codes have separate purpose namespaces, a 60-second lifetime and atomic single-use redemption. Pending codes store a source session reference, not its raw JWT. Redemption checks source-session revocation, JWT expiry and account suspension; logging out or revoking all sessions invalidates pending grants immediately at redemption.

A successfully exchanged code creates an independent session. Logging out of one client does not implicitly log out the other; revoke all sessions for account-wide logout. PKCE validation failures do not consume the legitimate client's code.

This backend-only hardening needs no database migration or new App build. Existing unredeemed legacy login tickets are intentionally rejected after deployment; users can request a fresh link. Clear/rebuild application caches and restart long-lived PHP workers using the normal deployment procedure. Regression checks: `tests/session-authorization.php`, `tests/fastai-browser-login.php` and `tests/fastai-release-login.php`.


## Browser HttpOnly authentication

The native Bearer contracts remain supported. Browser mode (`X-Browser-Client: user|admin`) instead uses scoped HttpOnly cookies, synchronizer CSRF and exact allowed Origin validation. Browser authentication responses contain only browser-session metadata, not accessToken. GET/POST/DELETE `/auth/browser-session` bootstrap, migrate legacy localStorage credentials during a bounded window, and revoke the current scoped browser session. See [browser-sessions.md](../browser-sessions.md) for deployment, expiry, CORS and compatibility details.

### Remaining compatibility boundaries

The no-op `me/invitations/retired-codes` endpoint and its shared Action have been removed; anonymous and authenticated calls return 404 and cannot create invitation codes. Registration still explicitly rejects old invite-code inputs, rather than silently ignoring them.

Keep the following until their consumers or historical data have been migrated: browser token exchange (default deadline 2026-10-21 UTC, configurable), V1 administrator authentication/profile dependencies, legacy payment callbacks and installed node/client contracts, old download URL and theme-footer fallbacks, historical invitation cleanup, financial/traffic entitlement conversion and upgrade migrations. The no-op SendTelegramJob consumes previously serialized messages; telegram:notify supports external cron; v2board:update safely redirects operators to update.sh. A source-only audit cannot prove that deployed queues, external cron or older clients no longer need these boundaries.
