# 登录安全检查与升级兼容

## 当前认证方式

用户网页和管理后台使用分离的 HttpOnly Cookie 与共享缓存中的服务端会话，前端请求携带 `X-Browser-Client: user|admin` 和 `credentials: include`。写操作（包括登录、注册及旧令牌迁移）需要内存中的 CSRF Token 和精确允许的 Origin。Cookie 为 host-only、SameSite=Lax，生产必须启用 Secure 和 HTTPS。浏览器模式忽略调用者在 Authorization、查询或 auth_data 请求体中指定的凭据。实际规则见 [浏览器会话](browser-sessions.md)；独立部署还需遵守同站约束。

原生 App 保持 HS256 JWT 与共享缓存中的会话登记。`AuthService` 在缓存查询前拒绝非字符串或空凭据，每次验证签名、有效期、会话登记及当前账户权限；不存在命中旧用户信息缓存就跳过 JWT 校验的路径。密码使用散列校验。隐藏订阅地址不能替代后端鉴权。

- 新签发的底层会话有 30 天绝对有效期；浏览器另有用户 7 天、管理员 12 小时的空闲期限，不能超过底层会话有效期。旧原生 JWT 没有 exp 时仍需有效的会话登记；迁移到浏览器时重新签发有期限的会话并撤销旧令牌。
- 浏览器退出使用 `DELETE /api/v10/auth/browser-session`；原生当前会话退出使用 `DELETE /api/v10/me/session`。单会话撤销不退出其他设备；改密、找回密码和全会话撤销使该账户的旧会话失效。会话列表不返回其他设备的凭据。
- 离线退出先清理界面状态并保存不含凭据的待退出标记，下次联网启动先完成服务端撤销，再恢复会话；离线时不能承诺服务端已退出。
- 旧 localStorage 凭据仅用于限时迁移，默认截止 2026-10-21 00:00 UTC，可通过 `BROWSER_LEGACY_EXCHANGE_UNTIL` 设置。迁移成功或明确过期/拒绝后清除旧凭据；正常登录不再写入 localStorage。非凭据的跨标签页状态标记仍使用 localStorage。
- 登录失败计数与限流继续执行。Google reCAPTCHA 已移除；可选 Passkey 登录需在后台安全设置开启并由账户在安全中心绑定。管理员权限实时检查，封禁管理员不能访问管理接口；可选 MFA 的配置及恢复流程见 [MFA](mfa.md)。员工角色和接口已退役。

## 安装升级与登录状态

完整升级按 [update.sh 流程](update-script.md) 执行。保留 APP_KEY、共享 Redis/cache 配置和会话键；脚本定向清理配置、路由和视图缓存，不清空应用缓存。不要执行 `artisan cache:clear`、清空 Redis 或切换到空的会话库来完成升级，这些操作会导致会话失效。

Cookie 迁移本身不需要数据库迁移，但完整版本升级仍需执行脚本批准的其他迁移。部署前后端配套代码，设置生产环境和精确来源；不能因为保留 APP_KEY 就承诺所有旧浏览器永不重新登录，迁移窗口结束、会话过期/撤销或权限变化都会要求重新认证。正常请求不会自动续期底层 JWT 的绝对有效期。

## 订阅凭据

账户安全页使用 `POST /api/v10/me/subscription/credential-rotations` 重置订阅凭据；旧用户 GET 重置接口已退役，不再作为兼容入口。操作更换订阅 token 和连接 UUID，旧链接及已导入配置失效，设备需重新导入；不修改密码、套餐或账户会话。复制、导入和二维码仍包含真实订阅凭据，应妥善保管。

## 历史改造记录

历史提交 b359bc83 修复签名/过期验证和会话撤销；6ab3689c 去除 URL auth_data；941cd206 将一次性授权码绑定来源会话。它们完成时浏览器仍使用 localStorage/Bearer；2026-10-07 的后续迁移已替换这一存储方式。旧的任意来源 CORS、credentials: omit 和“Cookie 尚待实施”说明不再适用于当前代码。当前 CORS 由 `BrowserOrigins` 与 `CORS` 中间件执行，不能只根据通用配置文件的默认值判断。

## 员工数组凭据绕过复核

员工接口此前按既有合同保留在 V1，现已按明确要求全部退役，`/api/v1/staff/*` 返回 404；没有迁移到 V10。以下为此前保留期间的鉴权复核：`AuthService::activeClaims()` 在缓存查询前拒绝非字符串和空凭据，所有 JWT 都必须验证签名与有效会话；`decryptAuthData()` 从数据库读取当前权限，不再通过 JWT 用户缓存短路验证。`Staff` 不接受 GET 查询参数中的 `auth_data`。因此原始攻击在退役前就已被 403 拒绝，退役后则由路由层返回 404。

退役前员工 `getUserInfoById` 已使用字段白名单，不返回密码散列、密码算法/盐、订阅 token 或 UUID。现在专用控制器、请求类、路由类、中间件和内核别名均已删除，测试不再通过临时路由加载这些死代码。`User` 默认隐藏密码材料与管理员显式字段投影继续保留并独立验证。

回归复用 `tests/auth-security.php`：保留共享 JWT 的数组/标量异常凭据检查，验证 11 个退役 URL 对匿名及有效历史员工会话均返回 404、不包含目标密码或订阅凭据；原始攻击对普通、特权及不存在的目标都不能查询。仍在使用的管理员鉴权继续验证表单/JSON 数组拒绝及角色实时降级。专项测试直接请求退役 URL，确认改密、封禁、邮件操作无副作用；不再注册员工测试夹具。仅在隔离项目与测试数据库执行，不遍历线上用户。

## 其他保留接口的认证与字段边界

- 旧用户业务接口已移除。保留的 V1 管理/运营接口在非浏览器模式下按原合同接受请求头或 POST JSON/表单凭据，拒绝 URL 中的 `auth_data`；浏览器模式只使用作用域 Cookie，不能用请求体或查询覆盖。
- `client` 中间件只接受非空字符串订阅凭据，再进入原固定、一次性或时效 token 校验；数组不能被 SQL 参数处理或缓存键插值接受。自定义订阅路径共用此中间件。
- 管理员 `user/fetch`、`user/getUserInfoById` 使用字段白名单，移除原始密码材料、token、UUID。列表内部仍用 token 生成管理员有权复制的 `subscribe_url`；CSV 导出仍按原管理合同包含订阅链接，不能描述为“所有响应均无订阅凭据”。详情中的邀请人只返回 ID 与邮箱。
- 管理员修改用户密码、邮箱或封禁账户时，在保存成功后撤销该用户全部旧会话；与找回密码的撤销规则保持一致；员工修改接口已移除。
- 成功的原生登录可返回本人的 JWT/订阅 token，已认证的节点用户同步可返回所服务用户的连接 UUID；这些是协议要求，分别依赖账户认证与节点共享密钥，不能与匿名或跨角色泄露混淆。
- 路由回归遍历实际注册的 V1 管理/运营/客户端保护入口，以缺失凭据、数组查询、JSON 数组及伪造请求头验证鉴权先于业务处理；退役员工和旧用户入口另测 404；V1/V2 节点入口另测缺失、数组与错误密钥。旧支付/Telegram 回调继续走共享验签或回调凭据检查。
