# 登录安全检查与升级兼容

当前网页使用 HttpOnly Cookie 与共享缓存中的服务端会话；原生 App 保持 HS256 签名 JWT 与 Redis 会话登记。此前浏览器 localStorage 保存令牌的流程已迁移，详见 browser-sessions.md。密码使用散列校验；JWT 必须通过签名和会话登记验证。隐藏界面的订阅地址不是令牌加密，也不能替代后端鉴权。

## 本次修复

- 原先命中 JWT 用户信息缓存时跳过签名、过期及会话登记检查。现在每次请求都验证 JWT 和会话登记，并读取最新账户权限，不再信任旧的 JWT 用户缓存。
- 单会话移除立即生效，顺带删除旧缓存。账户退出通过 `POST user/logout` 撤销当前会话，不撤销其他设备；无法联网时只能清理本机令牌，无法承诺服务端撤销成功。
- 会话列表不再返回其他设备的 `auth_data`。
- 新令牌带 `iat` 和 `exp`，签发后30天到期。旧令牌不强制新增过期要求，仍须保持有效的 Redis 会话。此兼容选择意味着旧会话暂时没有统一绝对超时；它们仍会在退出、移除会话、改密或找回密码后失效。
- 登录失败计数按规范化邮箱聚合，修正默认启用但没有累计次数的分支。登录接口增加每IP每分钟30次限制；共享出口可能触发该限制。
- 开启 reCAPTCHA 时，登录服务端也校验挑战；缺失或无效挑战拒绝登录。关闭该设置的站点保持原来的邮箱密码流程。
- 已封禁的管理员不得通过管理权限中间件。员工角色及接口已退役；用户封禁说明页仍遵循原来的账户状态逻辑。

## 本次升级对登录状态的影响

不修改 APP_KEY、Redis 会话键、localStorage 存储键或用户密码，不批量清理会话，无数据库迁移。正常旧会话继续使用；原先已撤销却被缓存错误放行的会话，以及不再具备权限的管理账户，会被正确拒绝。新登录在30天后需要重新登录，未实现自动刷新或空闲超时。

现有 update.sh 清理配置、路由及视图缓存，不执行应用缓存清空。部署不要清空 Redis、执行 `artisan cache:clear`、修改 APP_KEY 或更换到空的会话缓存库，否则仍会导致用户退出。修改密码和找回密码继续撤销该账户全部会话。

## 历史迁移方案（已于 2026-10-07 实施）

浏览器更适合使用 Secure、HttpOnly、SameSite Cookie 与服务端会话，配合 CSRF、受信任 Origin/CORS 限制、明确空闲/绝对超时和敏感操作重新认证。当前 CORS 配置默认允许任意来源，但不允许携带 Cookie 凭据；迁移 Cookie 前仍必须收紧来源并设计 CSRF 防护，不能只将 JWT 搬进 Cookie。外部客户端可继续使用受控的 Bearer 令牌，管理账户宜再加多因素认证。

可以通过过渡期交换接口，在用户原有 JWT 和 Redis 会话均有效时换发 Cookie，再清理本机旧令牌；过渡期结束后停用浏览器旧令牌。直接停用 JWT/localStorage 会要求当前浏览器重新登录，因此本次没有强制切换。邮箱密码本身可以继续保留，先改进会话管理比单纯换登录按钮更有针对性。

依据：[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[OWASP 浏览器存储安全](https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html)。本次属于针对代码的检查和回归验证，不是完整渗透测试；没有证明生产环境存在可利用的 XSS，也未验证真实 reCAPTCHA 服务、生产 Redis、反向代理 IP 或 TLS 配置。

## 订阅凭据

重置入口移至账户安全，需要确认。新界面使用 POST，保留旧 GET 接口供旧客户端兼容。该操作更换订阅 token 和连接 UUID，旧链接及已导入配置失效，需要所有设备重新导入；不修改密码、套餐或账户会话。界面不再展示订阅地址明文；复制、导入和二维码仍使用真实凭据，应妥善保管。


## 2026-10-07 迁移前的存储方式复核

历史提交 b359bc83 完成签名/过期验证、会话撤销和退出清理；6ab3689c 去除了 URL 中的 auth_data；941cd206 将一次性授权码绑定来源会话。这些改造没有迁移网页令牌存储方式。当前 shared/api.ts 从 localStorage 读取令牌，UserAuth.tsx 和 user/app.tsx 仍将登录结果写入 localStorage，请求使用 Bearer 并设置 credentials: omit。用户与后台使用不同存储键，但都可被同源 JavaScript 读取。HttpOnly Cookie 迁移仍是后续工作；当前风险不等于已确认生产存在 XSS。


## 2026-10-07 HttpOnly 迁移完成

新网页与后台不再写入或读取 localStorage 作为常规认证凭据。仅迁移入口在有限过渡期内读取旧 Token 并换成新的 HttpOnly Cookie 会话，同时撤销该旧 Token。双向免登录、App Bearer、权限检查和全会话撤销保持兼容；CSRF、Origin 与 Cookie 属性详见 [browser-sessions.md](browser-sessions.md)。上述旧版检查记录说明当时的状态，不代表迁移后的当前实现。

## 员工数组凭据绕过复核

员工接口此前按既有合同保留在 V1，现已按明确要求全部退役，`/api/v1/staff/*` 返回 404；没有迁移到 V10。以下为此前保留期间的鉴权复核：`AuthService::activeClaims()` 在缓存查询前拒绝非字符串和空凭据，所有 JWT 都必须验证签名与有效会话；`decryptAuthData()` 从数据库读取当前权限，不再通过 JWT 用户缓存短路验证。`Staff` 不接受 GET 查询参数中的 `auth_data`。因此原始攻击在退役前就已被 403 拒绝，退役后则由路由层返回 404。

退役前员工 `getUserInfoById` 已使用字段白名单，不返回密码散列、密码算法/盐、订阅 token 或 UUID。现在专用控制器、请求类、路由类、中间件和内核别名均已删除，测试不再通过临时路由加载这些死代码。`User` 默认隐藏密码材料与管理员显式字段投影继续保留并独立验证。

回归复用 `tests/auth-security.php`：保留共享 JWT 的数组/标量异常凭据检查，验证 11 个退役 URL 对匿名及有效历史员工会话均返回 404、不包含目标密码或订阅凭据；原始攻击对普通、特权及不存在的目标都不能查询。仍在使用的管理员鉴权继续验证表单/JSON 数组拒绝及角色实时降级。专项测试直接请求退役 URL，确认改密、封禁、邮件操作无副作用；不再注册员工测试夹具。仅在隔离项目与测试数据库执行，不遍历线上用户。

## 其他保留接口的认证与字段边界

- 旧用户接口不再接受 URL 中的 `auth_data`；请求头优先，兼容 POST JSON/表单凭据。退出操作使用相同的凭据来源，查询参数不能覆盖被验证的请求头。
- `client` 中间件只接受非空字符串订阅凭据，再进入原固定、一次性或时效 token 校验；数组不能被 SQL 参数处理或缓存键插值接受。自定义订阅路径共用此中间件。
- 管理员 `user/fetch`、`user/getUserInfoById` 使用字段白名单，移除原始密码材料、token、UUID。列表内部仍用 token 生成管理员有权复制的 `subscribe_url`；CSV 导出仍按原管理合同包含订阅链接，不能描述为“所有响应均无订阅凭据”。详情中的邀请人只返回 ID 与邮箱。
- 管理员修改用户密码、邮箱或封禁账户时，在保存成功后撤销该用户全部旧会话；与员工修改和找回密码保持一致。
- 成功的原生登录可返回本人的 JWT/订阅 token，已认证的节点用户同步可返回所服务用户的连接 UUID；这些是协议要求，分别依赖账户认证与节点共享密钥，不能与匿名或跨角色泄露混淆。
- 路由回归遍历实际注册的 V1 管理/运营/员工/用户/客户端保护入口，以缺失凭据、数组查询、JSON 数组及伪造请求头验证鉴权先于业务处理；V1/V2 节点入口另测缺失、数组与错误密钥。旧支付/Telegram 回调继续走共享验签或回调凭据检查。
