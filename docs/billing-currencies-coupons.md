# 优惠券与人民币／美元计费

## 兼容规则

- 升级给已有用户、支付方式和历史佣金补充 CNY 币种标记，不换算余额、不改套餐人民币价格、不重写旧订单金额。
- 默认新用户币种仍是 CNY；管理员主动设置 USD 后，仅新建账号使用 USD。账号币种创建后不可修改。
- USD 套餐价格独立配置，空白表示该周期不可购买；人民币余额不能支付美元账号订单，也不会自动兑换。
- 人民币充值赠送规则和金额礼品卡维持人民币语义，不能直接用于美元账号。
- 原有收入报表继续统计人民币，价格与币种页面另按币种显示合计，不能把两种金额直接相加。

## 配置顺序

1. 备份数据库和部署配置，使用 `update.sh` 执行包含本功能的升级。
2. 后台“订阅管理 → 价格与币种”为在售套餐配置美元价格。
3. 配置支持的支付渠道及其收款币种，刷新汇率，再选择新用户默认币种。
4. 原有支付渠道默认人民币。跨币种结算目前支持 EPay、Paytaro、PaytaroQR、StripeCheckout；美元收款仅开放 StripeCheckout。

汇率来自 ExchangeRate-API，后台及结算页保留来源链接。自动任务每小时检查，但按 UTC 日期最多发起一次自动获取；失败保留上次有效数据。人工刷新有 60 秒间隔，超过 7 天的汇率不用于新支付报价。人民币到人民币支付不依赖汇率。

支付发起时固定该订单、该渠道的金额、币种、手续费和汇率快照。后续汇率刷新不会改变已发起支付的回调校验金额。跨币种支付需要用户确认实际付款金额；报价变化后重新展示确认，不自动重试扣款。

旧订单无快照时仍按原订单金额、手续费和币种验证；保留既有支付 SDK 签名和原生回调响应。重复成功回调不得重复开通或入账。汇率及支付配置变化不代表可以更换在途订单所属渠道的支付服务商。

## 优惠券

- 管理员发放、公开领取均进入个人券包，结算时选择可用券。
- 新模板使用百分比优惠；同一用户同一模板最多领取一次，领取时占用库存，条款保存为快照。
- 下单预占券，取消订单释放预占；已过期的券不会因为取消订单恢复有效期。
- 限制套餐、周期、有效期和所有权在服务端校验；并发领取不得超发。
- 保留历史优惠码兼容。已进入券包的模板须从券包使用，避免同一用户再通过代码重复享受。

## 验证与上线边界

隔离 MySQL 测试覆盖旧数据迁移（重复执行）、人民币余额购买及续费、取消退款幂等、自动续费防重复、优惠券并发领取、跨币种报价、Paytaro／PaytaroQR 回调与重复回调、Stripe 币种参数、返佣失败回滚。另运行现有订单、支付、用户 API 回归和前端全量测试及生产构建。

测试使用专用临时数据库和模拟支付传输，不产生真实扣款。上线后仍需用每个实际启用的支付渠道做一笔小额端到端验收，检查网关实际回调、签名、金额、币种和到账；本地通过不能替代服务商生产环境验证。
