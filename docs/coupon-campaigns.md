# 按用户范围发放优惠券

## 后台使用

优惠券管理 → 发放到用户券包，选择百分比券和发放范围：用户筛选、全员、指定 ID。筛选编辑器与用户管理共用，多个条件同时满足；注册时间和到期时间按管理员展示时区输入，服务器使用 Unix 时间比较。

“预览发放范围”固定当时的用户 ID 名单，显示匹配、待发放、已领取或禁用跳过人数及库存。预览有效期 10 分钟，不占库存；修改范围会取消旧预览。筛选值不持久化，避免存储 Token 等凭据。

核对人数后确认，服务端锁定批次和券模板，检查有效期、条款是否改变及库存是否足够，原子预留整批库存。不足时不会部分开始。预览后注册的用户不加入此次发放。

发放记录展示创建时间、范围、成功、跳过、失败、待发放及取消数量，并可按结果查询用户 ID 明细。只有创建批次的管理员可以确认或取消，其他管理员可以查看记录。取消仅作用于未发出的部分，已发出的券继续有效。

## 执行与一致性

`coupons:campaigns` 每分钟处理最多 200 位用户，可用 `--limit` 调整单次数量（上限 1000）。复用既有 Laravel 定时任务，无需新增独立守护进程。本地暂停 scheduler 时，批次保持待发放，可手动运行命令验证。

每个用户／模板只能有一个券包记录。逐人发放及库存调整在事务中执行；命令重复或并发执行、重复确认不得重复发券或扣库存。执行时重新检查已领取、禁用、已删除或券已过期的情况，跳过并释放对应预留库存。

意外异常回滚本次发放，延迟 60 秒再试，最多 3 次。最终失败释放库存并记录安全原因，不保存原始异常消息。批量发放是逐人事务，已成功部分不会因后续个别用户失败而撤回。

确认后的券条款冻结，后续编辑模板不改变已确认批次的优惠或有效期。停用领券入口不撤销已确认批次；需要停止时取消剩余发放。预留库存从可领取库存中扣除，公众领取及其他批次不能占用。

## 管理接口

接口位于既有 `/api/v1/{adminPath}`，沿用后台管理员鉴权及浏览器 CSRF 保护。

| 方法／路径 | 输入 | 输出 |
|---|---|---|
| POST coupon-campaign/preview | coupon_id, scope(all/filtered/ids), filter, user_ids（仅 ids，最多100） | 201，固定名单预览及 previewKey |
| POST coupon-campaign/confirm | preview_key, confirmed=true | 202，批次状态；重复确认复用原批次 |
| POST coupon-campaign/cancel | id | 取消剩余发放并释放库存 |
| GET coupon-campaign/fetch | current, pageSize（最大100） | 批次列表及 total |
| GET coupon-campaign/recipients | id, current, status（可选） | 用户 ID、状态、安全原因、券包 ID、尝试次数及 total |

旧 `coupon/issue` 最多100人的同步接口保留兼容。新页面使用批次接口。

## 邮件名单入口

风控与黑名单 → 邮件禁发名单，为独立管理页面；邮件日志保留链接到同一页面的快捷入口。IP、UA 和邮件名单继续各自控制对应行为。

## 验证

隔离 MySQL 测试覆盖固定名单、库存不足、重复确认／执行、条款冻结、共享筛选、越权确认、取消及重复取消退库存、领取竞态、预览过期、用户删除、无限库存和重复迁移。前端测试覆盖明确选择全员、预览、确认勾选、防重复提交、库存不足和修改范围。
