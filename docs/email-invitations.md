# 邮件邀请与账户设置

通知设置与账户安全通过右上角头像菜单进入，也可从账户页的两个独立按钮进入。通知设置仅修改原有 `remind_expire`、`remind_traffic` 字段，账户安全沿用修改密码并退出旧会话的流程。两项功能不增加主导航。

邀请好友页使用发送邮件、跟踪邀请两个入口。邮件绑定收件邮箱，链接7天内有效且只能注册一次；数据库只保存令牌哈希，API和邀请记录不返回令牌。重发会使旧链接失效。每个收件邮箱60秒内不能重发，每位用户每天最多发送20次，同时有效的待接受邀请受 `invite_gen_limit` 控制。邀请跟踪支持最近7、30、90天，最多100条，展示排队、发送、接受、过期、发送失败状态。已发送表示邮件服务接受发送，不保证进入收件箱。

旧公开邀请码不再展示、生成或用于新注册；旧链接不再生效。历史邀请码记录没有批量删除，已有用户邀请关系和佣金计算保留。`invite_force` 仍控制是否必须受邀注册，但改为要求有效邮件邀请；`invite_never_expire` 不再用于新邀请。

## 部署

本次新增 `v2_email_invitation` 表，不增加用户表字段。请先备份数据库，再按已有发布流程更新代码。新版 `update.sh` 已包含这项迁移；使用脚本完成升级后无需再执行。若使用手动发布，在开放站点前执行：

```bash
/www/server/php/81/bin/php artisan migrate --path=database/migrations/2026_10_02_000001_create_email_invitations.php --force
/www/server/php/81/bin/php artisan route:clear
/www/server/php/81/bin/php artisan view:clear
```

迁移支持重复执行。静态资源已打包在 `public/console`，生产无需 Node.js。重启 PHP-FPM 和原队列进程以加载新任务代码，并确认 SMTP 配置、站点 `app_url` 正确，队列消费 `send_email`。注册关闭时禁止发送邀请；邮件验证、验证码和邮箱白名单规则仍然适用。

## 受邀用户流量奖励

后台「系统配置 → 邀请与佣金」配置「受邀注册奖励（GB）」和「受邀首次使用奖励（GB）」。分别留空或设为 0 关闭；开启前先在订阅设置选择有效的额度基础权限组。奖励进入独立额度余额，不改变套餐、有效期、佣金比例或佣金结算条件。仅设置首次使用奖励时，新用户仍需要试用、购买或其他额度才能开始使用。

只为启用后通过有效邮件邀请新注册的账户登记奖励，不补发历史注册用户。注册时保存两项金额；后台后续调整仅影响新注册，已登记的首次使用奖励继续按原承诺兑现。首次实际流量由服务器上报并记账后触发，不以登录、打开页面或导入配置作为使用。每账户每阶段只发一次；重置已用量不会重新触发。封禁账户不发首次使用奖励。日志见 v2_traffic_credit_log 的 invite_register / invite_first_use。

升级需执行新增迁移 `2026_10_05_000001_create_invitation_rewards.php`，完整 update.sh 已纳入该迁移。必须先完成迁移再启动队列/流量任务；仅 git pull 不足以完成此次部署。数据回滚需协调备份，不能删除奖励表后继续沿用已发余额。

V10 `GET /me/referrals` 新增 rewards.registrationBytes / firstUseBytes（整数 bytes，0 代表对新注册关闭），前端邀请页按实际启用项展示；原佣金保持不变。`GET /me` 新增 ticketCreation（allowed / purchase_required / closed），与工单创建共用后台规则；已存在工单的查看、回复不受新建开关影响。

验证：tests/invitation-rewards.php 覆盖默认关闭、奖励余额/权限、真实流量触发、重复/重置不重复、封禁、V10 字段；原邮件邀请与流量额度测试继续回归。

## 额度有效期
购买额度按每笔到账日起算 12 个日历月；邀请赠送通过 `invite_credit_months` 设置，默认 1 个月，可设 1–120 个月。邀请注册时快照有效期，注册和首次使用奖励分别从实际到账日起算，不追溯修改。奖励金额 0/留空关闭奖励，有效期留空使用默认 1 个月。

`v2_credit_batch` 按批次保存剩余量与到期时间，套餐优先，超额后最早到期额度优先。过期额度不进入可用余额或节点授权；`credits:expire` 每分钟清理并记账。GET 查询不写入数据。升级时已有余额从升级日起保留 12 个月，更新脚本包含批次迁移；执行迁移期间需保持原有维护/暂停 worker 流程。

验证：`php tests/credit-expiry.php` 覆盖混合扣减、到期授权、重复清理与账本一致性。
