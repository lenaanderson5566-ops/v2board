# 前后台验证

本文维护当前验证方式和人工验收清单。旧日期章节、逐轮测试计数、过时界面方案及发布记录通过 Git 查阅；历史通过结果不代表当前版本已验证。功能行为分别以对应文档和当前代码为准。

## 自动检查

在可销毁副本中执行；数据库、缓存和外部服务隔离要求见 [测试组织](test-organization.md)。

```sh
php tests/run.php --validate
php tests/run.php --only=console-smoke,console-verify,frontend-runtime
cd frontend
npm test
npm run build
```

前端组件测试与模块相邻，专题命令见 `frontend/package.json`。构建会执行 TypeScript 检查及静态资源打包；需核对 manifest 引用的文件齐全，再部署生成的资源。生成契约检查见 [项目结构](project-structure.md)，接口检查见 [V10 验证](api-v10/audit.md)。

针对修改范围运行现有模块。路由和节点使用 `Nodes.test.tsx`、`admin-linkage.test.ts`、`node-routes`、`node-v10`；Lightsail 使用 `AdminLightsail.test.tsx`、`lightsail`；浏览器认证、支付及安全变化同时运行对应后端模块。不要仅因测试名称含旧接口、迁移或历史漏洞而删除断言。

## 本地浏览器夹具

以下脚本只在独立 local 环境、测试数据库中手动执行，不属于自动测试入口：

```sh
php tests/console-ui-fixtures.php setup
php tests/user-experience-fixtures.php setup
# 完成人工检查后恢复
php tests/user-experience-fixtures.php cleanup
php tests/console-ui-fixtures.php cleanup
```

控制台夹具只创建带专用前缀的隐藏测试内容。用户体验夹具要求事先存在非管理员 `test@example.com`，会备份并临时修改其套餐字段；上次恢复文件存在时不能再次 setup。遵守脚本中的引用保护，清理失败时先核对引用，不强制删除数据或恢复文件。不要向夹具提供真实支付、邮件或云服务凭据。

## 浏览器验收清单

桌面与窄屏均检查加载、空数据、请求失败与重试；同时覆盖键盘焦点、弹窗关闭、滚动、字段标签和错误提示。

CSV 导出使用 60 秒超时，覆盖响应头等待和文件正文读取；失败提示确认操作结果后重试，不自动重复生成优惠券等数据。测试通过模拟中断验证超时和单次请求，不能证明大数据导出的线上耗时。

浏览器会话初始化的 15 秒超时包含 JSON 正文读取；超时清除未完成的初始化任务，后续请求可重新初始化。回归同时保留跨标签页切换账号时阻止旧表单提交、CSRF 刷新和离线退出的既有断言。

后台登录与密码重置使用 `Editor` 的 `warnUnsaved={false}`，凭据输入不显示“未保存”标记，也不注册离开提醒。后台路由保护仅在已登录状态启用；主动退出和会话失效后立即解除。`AdminAuth` 回归使用真实编辑器验证登录输入和卸载清理，`AdminApp` 验证退出、会话失效及已登录状态的路由保护；普通配置编辑仍保留未保存保护。

## 验证边界与记录

组件测试证明交互和契约，构建证明类型及资源可打包；两者均不能代替真实浏览器视觉验收。报告须区分自动测试、浏览器检查、真实节点和外部服务联调，并说明未执行的部分。

购买确认中的优惠券改为原位展开：默认单行摘要显示当前选择或预计节省金额，选择后立即更新价格、收起列表并恢复摘要焦点，不再打开嵌套选券弹窗或要求再次确认。优惠券列表随购买主体统一滚动，不可用券折叠显示原因；空券包、全部过期/已占用或使用、全部不适用当前套餐或周期时，隐藏整个优惠入口及占位间距；加载期间无可用券时也不显示入口。券包获取失败仍保留错误和重试入口，避免误报没有优惠。活动领取与券包管理仍保留在各自页面。保留用户主动选券及不使用优惠券的决定，不自动消耗其他券。CouponPicker、BillingFlow、CouponCenter、PaymentCheckout、PaymentPolling、localization 共 116 项自动测试通过，覆盖折扣取整、币种、适用范围、状态禁用、选券和取消、焦点恢复、订单参数及支付回归；类型检查和生产构建通过。此轮未进行浏览器视觉验收或真实支付，桌面及窄屏的长券名、多券滚动、键盘导航和购买按钮可达性仍需浏览器验收。无可用券隐藏的补充回归覆盖空券包、过期、已占用/使用、套餐与周期不匹配、加载和错误重试；保留不适用选中券的清理及订单金额/参数断言。 转化流程补充：有券未选时展示可选优惠及最大预计节省额，选中后显示券名和减免金额，不自动消耗券。切换周期保留仍适用的选择，失效时清除且切回原周期不擅自恢复；主动不使用的选择同样保留。购买底部展示套餐、周期和预计小计，只有选券后才显示优惠后小计，保持支付页最终计价说明。新增文案覆盖十四种语言，CouponPicker、BillingFlow、CouponCenter、localization 共 118 项测试通过。浏览器访问本地 5173 预览显示 HTML 被解析为 JSON 的运行配置错误，无法进入购买页；未完成视觉验收，未操作真实支付。

仪表盘回归在 `admin-workspaces.test.tsx` 验证系统状态失败不阻断经营数据、统一刷新、视图地址、币种隔离、趋势切换不重复请求、缺失日期断线、零值和非有限数值处理、键盘选择及明细表。窄屏图表可在容器内横向滚动，核心指标按屏宽切换列数。本轮内置浏览器访问本地预览超时，Computer Use 随后因无法确认浏览器 URL 终止；桌面和窄屏视觉验收未完成，合成预览文件不纳入发布。

共享后台组件回归覆盖操作菜单的实际高度定位、方向键入口、隐藏和禁用项排除，以及异步提示清理后旧请求完成的竞态。当前样式整理已通过前端全量自动测试；本轮本地浏览器工具连接失败，新的共享详情布局、阴影和筛选样式仍需桌面及窄屏视觉验收。历史轮次的浏览器记录不代表本轮已验收。

## 可选安全功能入口

删除账户页面以“了解删除影响 → 验证并确认”展示当前阶段，按账户登录、订阅权益、数据保留分行说明影响；余额、订单等阻碍项单独列出，可重新检查处理结果。检查失败时保留重试入口并暂停删除，检查发现功能关闭时隐藏整个入口。确认弹窗保留当前密码、近期安全登录要求、输入 `DELETE` 和勾选确认；提交期间禁止关闭和重复提交，取消后清空确认信息。`AccountPreferences.test.tsx` 覆盖说明内容、阻碍项刷新与失败重试、关闭开关、取消重开及提交保护，`localization.test.ts` 检查各语言文案。桌面与窄屏需核对阶段提示、影响说明、长翻译换行和确认表单；组件测试不替代实际浏览器视觉验收。信息结构参考 [Google 删除账号前的影响核对](https://support.google.com/accounts/answer/32046?hl=zh-Hans)和 [Microsoft 的删除前身份及事项确认](https://support.microsoft.com/en-us/accounts-billing/manage/how-to-close-your-microsoft-account)，删除是否可撤销仍遵循本站实际行为。

MFA 与 Passkey 设置卡片以服务端状态为准，加载时不闪现可开启入口。站点关闭且无历史绑定时隐藏；有历史绑定时保留管理和恢复。`MfaSecurity.test.tsx`、`PasskeyLogin.test.tsx` 覆盖开关、历史绑定和登录验证；`tests/mfa.php` 覆盖发起与确认之间关闭开关的拒绝行为。Telegram、账户自助删除和 iOS 共享账户下载入口仍使用各自开关；隐私偏好在统计关闭时保留用户选择。本轮以自动化与生产构建验证，未进行真实设备 Passkey 或生产 MFA 变更。

## 优惠券滚动与选择样式

优惠券列表不再创建独立滚动区域，由购买窗口的 purchase-body 统一滚动，底部金额和创建订单操作保持原有固定区域。外层采用细滚动条、透明轨道、稳定预留滚动条空间；鼠标悬停或键盘焦点进入时提高滑块可见度，强制颜色模式恢复系统滚动条。选项使用轻量背景、边框和原生单选控件保持选中反馈，鼠标悬停仅作用于可用未选项。保留焦点轮廓、禁用状态、触摸操作和窄屏换行。方案参考 [Adobe Spectrum 的单一滚动区域](https://spectrum.adobe.com/foundations/app-frame/content-area-browsing-context)与 [Microsoft Atlas 的细滚动条和稳定占位](https://microsoft.github.io/atlas-design/atomics/overflow.html)。本轮验证使用现有 CouponPicker 与 BillingFlow 测试及生产构建，不以组件测试替代浏览器视觉验收，未进行真实支付。


## 统一订阅结算

套餐目录进入独立结算页，周期、优惠券、支付方式和后端报价在同页展示；桌面端右侧集中显示价格及提交操作，窄屏纵向排列并保留底部操作区。确认后在当前结算页进入内嵌付款状态，地址保留套餐路径及可恢复的订单编号；刷新及支付回跳不会新建订单。浏览器检查使用既有合成预览夹具，验证年付选中、选券原位折叠和金额从 CNY 268.00 更新为 CNY 239.20，以及确认后进入合成二维码/等待状态。所有金额和账户均为夹具数据，不代表真实支付联调。完整前端测试通过后，布局调整再执行相关购买与多语言回归及生产构建；后端测试在可销毁副本及随机数据库中运行。

窄屏补充验收使用 390px 合成页面：周期优惠标签修正为整行展示，价格不再被标签挤成竖排；滚动后支付宝/微信支付选项均可达，切换渠道会更新选中态，金额与底部按钮不遮挡支付选项。桌面和窄屏截图保存在忽略的测试输出目录。


生产恢复路径复核：结算创建订单在本页切换付款阶段，并通过组件内存传递本次明确确认，不在地址或持久存储中放入自动支付指令；消费、退出和登录失效时清理，刷新订单仅恢复状态。已恢复订单的支付请求继续携带 UUID；禁用或失效渠道会重新加载候选项。复用 BillingFlow、PaymentCheckout、app 和 PaymentMethodPicker 回归，并检查生产构建中未包含合成账号、模拟报价和模拟订单标记。支付图标使用后台配置及通用图标兜底，真实渠道配置和资源可达性须在部署域名验收。 订单页刷新验收确认只恢复待支付页面并等待明确确认，不自动发起付款；合成数据截图保存在忽略的测试输出目录。
