## 本地检查

```sh
cd frontend
npm test
npm run build
cd ..
php tests/console-smoke.php
```

后台检查包含用户筛选和批量操作、订单、排序、节点配置、公告和知识库编辑。关键配置的业务语义见 [配置说明](critical-config-review.md)。用户接口验证见 [接口检查](api-v10/audit.md)。

检查桌面与手机的登录、充值、订阅购买、付款、工单和导入流程，特别核对加载、失败重试、字段保留及键盘操作。自动测试不代表真实 SMTP 投递、支付结算、节点连接或原生客户端唤起已验证。

### 本次落地

日志查询仍受原有保留期限约束；风控聚合仍限近 30 天，按固定 10 分钟合并。关键词为数据库 LIKE 匹配，海量日志应结合时间/IP 缩小范围，不能将当前实现视为全文搜索引擎。

### 专用客户端数据上报建议

有必要补充客户端独有的故障信息。现状：`lib/v2board/diagnostics.dart` 在内存保留最近 30 条脱敏 API 诊断；`network_diagnostics.dart` 支持本地网络检测与复制报告。后端访问日志能证明 API 请求结果，但不能证明代理核心成功启动或本地端口可以使用。

建议先实施用户主动的“提交诊断”，提交前预览内容并关联工单。拟新增 `/api/v10/me/diagnostic-reports`，遵循原生 Bearer 鉴权、固定字段白名单、大小上限、限流、过期删除及管理员权限。此接口是建议，本次未创建。

建议字段：应用版本/构建号、系统类型/主版本、内核版本、失败阶段（登录、拉配置、启动、连接）、规范化错误码、请求 ID、阶段耗时、代理模式、端口自检结果、诊断时间。后台按版本/平台/阶段统计失败率。

不收集浏览网址、DNS 查询历史、完整配置、节点密钥、Token、密码、订阅链接或原始堆栈。现有复制报告含探测目标和 DNS 答案，若改成自动上传不能直接照搬，应改成成功/失败与耗时等限定字段。设备关联优先随机安装标识，可重置，不使用硬件指纹。

自动上报可作为第二阶段：默认关闭、有清晰开关，仅记录失败事件和有限聚合，限制频率、重试次数、缓存大小，建议诊断保留 7–30 天。无需高频心跳；不得以客户端自报流量计费、自报在线状态替代节点数据。上报失败不能影响连接。

### 本地代理端口核对

- `FlClash/lib/models/clash_config.dart`：混合端口默认 7890；已有用户设置可能不同，以客户端显示为准。
- `FlClash/lib/v2board/singbox.dart`：生产运行配置生成 `type: mixed`、`tag: fastai-mixed`，`listen_port` 来自 `patch.mixedPort`；因此旧混合端口设置仍真实用于 sing-box。
- `FlClash/lib/views/tools.dart` 的本地代理地址与上述运行配置读取同一设置。HTTP 和 SOCKS5 可使用同一个端口，通常为 `127.0.0.1:7890`。
- 仅在非安全模式、端口大于 0、核心成功启动后才有监听；另一个代理程序占用同一端口会导致启动问题。安全测试版有意不建立代理监听，不能用来验证真实代理流量。
- sing-box 适配只生成 mixed 和按需 TUN 入站，没有映射旧 `port`、`socks-port`、`redir-port`、`tproxy-port`。旧独立端口不能直接承诺兼容。
- 此结论基于运行配置代码与已有测试，不是本次在用户主机打开代理后的实测。

## 注册至支付旅程梳理（2026-10-17）

| 环节 | 堵点或疑虑 | 本轮处理 |
| --- | --- | --- |
| 注册验证 | 收不到验证码时缺少操作指引；邮箱自动大写容易造成输入困扰 | 增加检查垃圾邮件、邮箱拼写和稍后重发提示；邮箱禁用自动大写与拼写检查 |
| 注册后登录 | 注册成功后自动登录失败，界面仍要求创建账户；启用人机验证时注册已消耗令牌 | 明确账户已创建、转为继续登录；不再要求已用邮箱验证码和重复勾选条款；人机验证使用新挑战；提交和重发共用即时锁 |
| 登录衔接 | 套餐、活动或订单入口在登录后丢失 | 保留已知本站购买路由，登录后恢复；不接受任意外部跳转地址，主动退出时清除 |
| 选套餐及下单 | 不知道购买步骤；请求超时后不确定是否已有订单 | 套餐页补齐流程步骤；不确定结果引导先查看订单记录，保留原有未完成订单拦截与服务端事务锁 |
| 支付金额 | 手机折叠订单详情同时隐藏跨币种实际付款信息 | 实际付款金额和币种移至常显金额区域；待确认时使用已发起报价或订单快照，避免展示当前渠道新报价 |
| 支付中 | 跳往渠道后不知道是否需返回；重新发起可能导致重复付款 | 增加返回页面、账单续查说明；重新发起增加确认，并先读取服务端状态，只有待支付时恢复渠道选择；网络失败保持等待状态 |
| 完成 | 付款完成与实际使用之间缺少明确指引 | 套餐完成页增加下载客户端、导入或更新订阅的下一步说明 |
