# 日志管理（2026-10-11）

## 用户旅程与体验统计（第二批）

后台“访问与转化”增加 `GET /api/v1/{adminPath}/analytics/journey?days=7|30|90&device=all|desktop|mobile|tablet`。沿用管理员鉴权、每分钟 30 次限流及 `private, no-store`；业务结果按日期/系统时区独立缓存，匿名体验结果额外按设备缓存，最多 60 秒。业务统计不受设备、匿名统计开关或同意状态影响。

- 首次使用：按系统时区划分注册日，注册日为第 1 日，只纳入已结束 7 个自然日观察窗的非管理员账户。以最早套餐 paid_at、其后的首条订阅成功日志及同窗正数日流量逐步计算人数；排除充值和流量重置，付款包含余额与零元。平均注册至付款、付款至订阅日志有准确时间；日流量只证明观察窗内有使用，不能证明订阅后的精确时序或客户端连接成功。
- 活跃/留存：今日及近 7/30 日按账户去重，成功登录与正数日流量分别统计；第 7/30 日使用各自完整观察注册批次，并统计窗口最后一个自然日。登录事件不覆盖已有会话访问；日志清理、漏报和历史时区变更可能造成缺口，因此明确称为观测留存。缺表返回不可用，零分母返回 null。
- 续费：以已完整观察 30×24 小时的首次非零金额套餐付款账户为样本，观察其后的非零金额 type=2 套餐付款，按账户去重。不同周期续费机会不同，不能解释为全站到期续费率。到期未恢复仅统计当前套餐到期至少 7×24 小时且到期时间在所示范围内的账户，不构造历史到期快照或历史流失率。
- 引导动作：下载点击、复制成功/失败、导入发起、帮助/文档打开。点击不代表下载完成、安装、阅读或连接成功，复制成功仅指写入剪贴板。
- 性能：官方 `web-vitals` npm 包（锁定 6.2.3）延迟加载，每个文档各指标只取首次可上报的 LCP/INP/CLS，归属启动监测时的页面；不将 SPA 后续视图视为独立文档指标。CLS 以千分之一单位保存。共享用户请求层最多采样每文档前 20 次接口调用的耗时和错误类别，排除调用方主动取消；脚本异常只留类别。没有接口地址、错误文本、堆栈、订阅凭据或账户身份。
- 数值直方图保存计数与和值，平均值使用原始数值，P75/P95 为固定桶上界估计。耗时数值上限 600000 ms、CLS 上限 100000 个千分单位，客户端上限截断；不支持或未收到样本时不补零。每会话最多 200 个非浏览事件，客户端每分钟最多安排 40 个统计事件，服务端原有限频继续有效，数据用于体验观察，不作风控或账务依据。

新增 `2026_10_19_000001_create_analytics_measurements.php`，只创建匿名 `v2_analytics_measurement` 聚合表（会话外键标识、固定页面/事件、桶、计数、和值），可重复执行；视图和原购买漏斗不因动作/性能事件递增。`update.sh` 已加入定向迁移、目标检查与白名单；必须运行完整更新流程，不能以全量 migrate 替代。既有 `logs:prune` 随匿名会话清理测量桶，继续遵守 7/30/90 日保留期，无历史回填。

V10 复用原 `/public/analytics/events`，增加可选 `event` 与 `value`，保留严格 Origin、JSON、1024 字节、字段白名单、同意、GPC/DNT 和限频。数值指标必须带整数 value，动作/错误事件不得带值，CLS 单独校验上限。隐私选择版本提升到 4：旧“允许”需重新同意，旧“拒绝”继续生效。新增说明已加入所有界面语言目录（中文提供中文说明，其余缺少专门译文的语言显示英文说明）。

## 运营与安全统计报表

后台“访问与转化”新增运营与安全报表，复用现有记录，不新增采集、数据库表或保留策略。`GET /api/v1/{adminPath}/analytics/operations?days=7|30|90` 沿用管理员鉴权，限流每分钟 30 次，服务端缓存最多 60 秒，HTTP 响应为 `private, no-store`。业务报表不受访问设备筛选、匿名统计开关或用户统计同意状态影响；各来源仍按自身日志保留期限制，界面明确提示缺口。

- 登录/订阅：按所选系统时区日历范围内的日志事件计算成功率、失败数、未知数、最近记录及失败原因排行。原因仅返回固定分类，历史异常字符串归入“其他”；不返回邮箱、IP、UA、订阅地址或日志 payload。订阅成功沿用日志语义，不等同于节点连接成功，也不覆盖未写入日志的请求失败。
- 风控：按命中时间选取，读取当前 `payload.review.state`。复核覆盖率为（确认 + 误报 + 忽略）/ 命中，误报率为误报 / 已复核；未复核不算有效命中，无分母返回 null。账户数按每条规则去重，不含 null 账户。
- 支付：按订单创建时间、当前/最终渠道和订单币种分组，展示 paid_at 付款比例、完成/折抵数、平均下单至付款时间；不推断支付尝试历史。回调按事件时间独立计数，保留重复通知与仅确认事件，不将回调数作为付款订单数。已付款待开通及最久等待是全部订单的当前快照。缺少实际扣款及独立开通时间，故不展示精确扣款至回调、到账至开通延迟。
- 邮件：按创建时间、服务商与邮件流汇总接受、失败、不确定、其他及送达/负面回执；发送中超过 120 秒视为不确定。传输耗时不含队列等待，服务商接受不等于送达，无回执不等于失败。
- 健康：复用系统健康检查、Horizon 工作量和每日任务记录，展示预计清空耗时、队列长度、进程数、失败任务库的全部保留条数、今日任务状态、最近成功及日志清理时间。读取失败显示不可用，不显示为健康零值。
- 访问：原有匿名会话报表增加小时、星期分布，按会话开始时间和系统时区归属，继续遵守设备筛选、保留期和同意要求。使用 UTC 15 分钟聚合后转换时区，支持半小时/四分之一小时时区，无需 MySQL 时区表。沿用原来源域名及顺序购买路径漏斗；不会将匿名来源归因到真实付款账户。

本轮没有新增迁移；已有表缺失时相应报表显示不可用，按正常升级流程补齐。结果只覆盖仍保留的数据，不保证历史采集完整。实际生产容量与查询耗时需在部署后的数据规模下观察。

## 已实现

- 系统日志：时间范围、级别、HTTP 状态码、完整请求 ID 检索，按时间与 ID 稳定分页，每页最多 100 条；后台默认查看最近 24 小时。
- 新日志写入独立 request_id、http_status、duration_ms 和路由模板字段。请求 ID、级别/时间、状态/时间具有索引，检索不扫描 context JSON。
- 日志展示采用明确字段白名单。旧记录的原始消息、URL 查询参数、请求体和异常 context 不再返回浏览器；旧路由模板缺失时显示提示。
- 节点 IP 上报不再删除连接日志，清理由独立定时命令 `logs:prune` 每 5 分钟在后台运行，无节点流量时也能清理。
- 每轮每类日志最多删除 1,000 条，一次最多 5 轮，轮间检查 20 秒运行预算。每个 DELETE 只针对本批主键，并重新检查过期/复核条件，不使用覆盖全部历史的大事务。
- 系统、登录、订阅日志补充时间索引；连接与 DDNS 已有时间索引，继续复用。数据库执行计划测试验证了请求 ID 与过期清理查询可用索引。
- 历史检索字段每次最多补齐 500 条，并检查 5 秒预算。忽略超过 8 KiB 或无效的历史 context，避免将大型异常记录批量载入内存。旧数据不在迁移时一次性重写。
- 定时与手工运行共用锁。后台显示最近成功清理时间、删除数量及补齐数量，便于检查调度器是否工作。

## 保留策略

在后台“系统日志 → 日志保留与清理”设置。保存配置不会同步执行删除；下一次调度按当次读取的策略处理。正在执行的批次继续使用启动时的策略。缩短期限意味着过期数据将永久删除。

| 日志 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| 系统 | 30 天 | 1–365 天 | 过去按一个自然月清理，现明确为天数 |
| 连接 | 原有设置，缺省 30 天 | 1–365 天 | 与风控页面使用同一配置，采样间隔不变 |
| 登录 | 0 | 0 或 30–365 天 | 0 不自动清理，建议需要时设置 90 天 |
| 订阅 | 0 | 0 或 30–365 天 | 至少保留 30 天统计窗口 |
| 风控命中 | 0 | 0 或 30–365 天 | 仅清理已确认、误报或忽略的记录；命中和最后修改时间都须过期，保留未复核及待复核记录 |
| DDNS | 30 天 | 1–365 天 | 只记录状态变化及实际 DNS 更新 |

登录、订阅与风控清理默认关闭，升级不会自动启用新的历史数据删除策略。缺失时间戳的旧记录不推断过期时间，不自动删除。流量统计、在线快照、风控配置及账务数据不由 `logs:prune` 清理；`reset:log` 原有两个月流量统计保留策略不变，系统日志部分改为调用统一清理命令。

## 后台接口

沿用管理接口及权限，不迁移到 V10：

- `GET /api/v1/{adminPath}/system/getSystemLog`：兼容 current/page_size 及旧 level filter，新增 level、status、request_id、from/to（Unix 秒）。返回 data/total，记录含 id、title、level、method、uri、request_id、http_status、duration_ms、created_at。不再返回 data/context、IP、host 等原始字段。
- `GET /api/v1/{adminPath}/system/logRetention`：返回 data.settings 与 data.lastRun。
- `POST /api/v1/{adminPath}/system/logRetention`：可部分保存上述 `*_log_retention_days` 字段；需要管理员权限。连接日志原有风控接口保持兼容。

## 部署与验证

发布时执行完整 [update.sh 升级流程](update-script.md)（按批准清单定向迁移，勿执行全量 migrate），确保 Laravel scheduler、共享缓存和后台进程正常工作；更新后重启常驻队列/调度进程，使其加载新的日志处理器。大量历史日志的索引创建可能耗时，应安排适合的维护时段。旧检索字段逐批补齐期间，request ID/状态筛选只覆盖已索引记录；日期/级别查询仍可查看所有历史记录。

可在维护时手动执行 `php artisan logs:prune`；这是实际清理，不是预览。配置保留期前确认业务所需时间范围。`reset:log` 保持原有命令兼容。

回归测试：`php tests/log-management.php`（本地环境，事务回滚）、`php tests/node-v10.php`、`php tests/node-ddns.php`，以及前端 `AdminSystemLogs.test.tsx`。不向外部日志服务发送数据。

## 仍保留的边界

新增日志不采集请求体、查询值、任意消息或异常对象。旧数据库、文件日志及备份中的敏感内容不会被本次字段回填抹除；接口隐藏与物理清除是两件事。待复核风控记录不会自动到期，需运营人员完成复核。OpenRC 节点文本日志仍由主机轮转策略管理，systemd 使用 journal 策略。

暂不引入外部日志平台、全量节点日志上传或自动告警；有实际容量与告警需求时再扩展。
