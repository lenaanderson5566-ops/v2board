# 节点管理界面

Cloudflare DDNS 从侧栏整合到「节点管理 → Cloudflare DDNS」。旧的 `#/ddns` 链接仍能打开对应标签页。凭据加密、节点上报、DNS 更新和 DDNS 日志接口保持不变。

节点列表、Cloudflare DDNS、Lightsail IP、服务器流量统一为并列标签页。Lightsail IP 和服务器流量直接在页面中管理；Lightsail 的编辑及更换确认仍使用对话框，保留实例名称确认、失败恢复及轮询流程。各标签页独立加载，返回节点列表刷新数据。

节点列表显示全部节点、V2Node、V2Box 和额度受限节点数量；支持按 ID、名称、域名、当前 IP、协议搜索，按后端和额度状态筛选。列表增加协议列。切换回节点列表时刷新数据，已有编辑、部署、排序、服务器流量和 Lightsail 操作保留。

「显示设置」支持逐列勾选和恢复默认展示，选择自动保存在当前浏览器（`admin.nodes.columns.v1`）；默认显示全部信息列，操作和拖动排序始终保留。权限组按 ID 对应名称，兼容数字和字符串 ID；找不到的权限组显示「未知权限组（ID）」，便于排查已删除或失效的关联。

管理后台用户标识统一显示 `ID: 123 · user@example.com`，涵盖用户列表、订单列表/详情、佣金记录、工单列表/对话、流量排行及风控记录。用户删除后仍保留历史 ID，并显示「邮箱不可用」。筛选字段保持原语义，不改变用户 ID 或邮箱的筛选方式。

订单、佣金和工单邮箱由管理员接口补充，只投影邮箱字段，不返回用户模型。分页列表使用一次批量查询，无逐条查库；用户流量排行也改为批量查询邮箱。用户业务 API 不增加这些管理员字段。

验证：`php tests/admin-user-identity.php`（仅 local 环境）；前端相关测试与 `npm run build`。

运行状态、配置同步判定及系统健康检查见 [管理后台运行诊断](admin-diagnostics.md)。


## 节点访问目标统计的容量与保留

开关仍在「日志设置」，默认关闭；报表在「访问与转化 → 节点访问目标」。报表展示估算缓存预算、累计接收字节和容量拒收批数；累计指标在连续空闲一小时后过期，不是滚动一小时账单或 Redis RSS。关闭不影响计费。统计采用五分钟时间桶，显示当前及此前 11 个桶；边界附近实际覆盖约 55–60 分钟，数据从所在桶起始时刻一小时后过期。

接收路径使用专用 Redis 缓存存储，不跟随应用的 file/array 缓存驱动。每批仅原子更新当前桶，不再搬运整小时状态；每桶最多 500 行，每节点最多保留 1,000 个一小时内批次 ID，全站估算准入预算默认 64 MiB（`TARGET_STATISTICS_CACHE_BUDGET_MB` 可设为 8–1024，更新配置缓存并重载进程后生效）、最多 4,096 个桶/批次容器。预算包含预估 Redis 对象开销，但不是进程硬内存上限；应通过 Redis 自身的 maxmemory 和监控控制物理内存。预算耗尽返回 429，不逐条淘汰去重信息，不回退写文件或数据库。过期预算索引分批回收，短时可能保守拒收。上报体不超过 256 KiB；按已认证节点限制每分钟 30 次，不按来源 IP 共用额度。

新节点可在「日志设置 → 节点访问目标统计」选择 30 秒、1 分钟、2 分钟或 5 分钟，默认 1 分钟，最多另加 10% 抖动。修改周期独立保存，不清空已有汇总或重新开启采集；开关和周期互不覆盖。策略刷新最多间隔约 60–66 秒，独立于上报周期；失败批次约 30–33 秒重试，避免长周期超过五分钟重试保留时间。旧节点忽略新字段、沿用固定周期，报表节点选项以“周期固定”区分；升级节点后报告 target-statistics-interval-v1 能力。租约最多 120 秒，配置响应的可选策略头减少独立轮询。关闭后面板立即拒收，节点同步或租约到期停采。UDP 每连接最多缓存 64 个地址，每节点最多 8,192 地址及 1,024 个持有缓存的连接；TCP 只缓存一个固定目标。达到容量时可丢失统计，计费保持独立。

默认 Redis 连接沿用现有缓存主机和库；可通过 `TARGET_STATISTICS_REDIS_URL`、`TARGET_STATISTICS_REDIS_DB` 指向独立实例。若要求目标信息只存在于短期内存，应在独立实例上关闭 RDB/AOF、限制访问并排除备份；不要为了统计修改共用 Redis 的队列或计费持久化策略。TTL 控制在线数据有效期，无法擦除既有备份。升级后旧 v1 汇总不迁移，旧 Redis 项按原 TTL 过期；旧文件缓存与备份按原运维保留策略清理。节点优化需升级二进制，仅更新面板即可与旧节点兼容并使用新的接收存储。


## 部署与接入

节点列表将原「接入与凭据」和「安装命令」合并为「部署与接入」抽屉，分部署、凭据管理两页；子节点只提供父节点接入入口。新安装和已有节点升级分别显示，手动安装、IP 查询及 DDNS 引导收在折叠区域。

V2Box 新安装：生成一键部署命令、复制后在 Linux 节点以 root 执行。不需要在服务器再次粘贴长期密钥。命令包含十分钟内有效、仅可兑换一次的部署授权；生成新命令会作废旧命令，生成本身不改变正在使用的凭据。兑换时才生成独立密钥，并保留既有手动轮换的宽限/冲突保护。命令不存浏览器持久化存储，授权仅在 Redis 以哈希索引保留短期元数据；管理员权限/密码或节点凭据变化会阻止旧授权兑换。网络响应丢失时不重复返回密钥，需要重新生成授权并按凭据状态恢复。

部署脚本先完成固定 v1.0.2 正式安装包的下载校验，再兑换授权；授权从 stdin 读取，通过私密 curl 配置文件送入 Authorization，不放入 URL 或长期密钥命令参数。配置使用同目录临时文件原子写入，权限 0600；临时凭据文件退出清理。已配置的节点会拒绝新安装流程，必须使用升级命令或 v2box credential；升级保留现有配置。V2Node 保留兼容性提示和手动安装。

抽屉区分独立凭据是否认证与节点运行状态；检查接入状态仅验证当前有效密钥的最近认证，不把旧宽限密钥或认证请求当作节点运行正常。全局密钥迁移仍收在凭据管理的高级折叠项，不再要求重复输入管理员密码，保留管理员登录鉴权及操作确认保护。

V2Box 参考原 V2Node 的“wget 下载安装入口，再执行并传参”结构，长依赖检查移入面板提供的公开静态脚本。手动安装和升级命令为 wget 下载 install-v2box.sh 后由 sh 执行 --install；脚本自动安装 curl、bash、jq、unzip、coreutils 和 CA 证书，再转入正式 v1.0.2 安装器。sh 入口兼容最初未安装 bash 的机器。以 Linux root 执行，下载入口需先有支持 HTTPS 的 GNU wget，并能访问面板、系统软件源和 GitHub。一键授权部署使用私有临时目录和 stdin 授权，仍不暴露长期密钥；原 V2Node 安装入口保持不变。

后台“生成一键部署命令”输出单行命令，包含面板地址和节点 ID，并通过 stdin 自动传入十分钟一次性授权；复制执行即可自动写入独立密钥，不触发密钥输入提示。长期密钥不进入复制命令。脚本核对兑换结果与指定节点 ID，一旦不匹配即拒绝写入；原有 URL/授权双行 stdin 命令继续兼容。
