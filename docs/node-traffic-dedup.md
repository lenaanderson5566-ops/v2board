# V2Box 流量批次去重

仅 V2Box V10 流量接口增加可选 UUID `batchId`。没有批次 ID 的旧 V2Box 保持现有路径。新版配置返回 `trafficBatchDedup: true` 后，节点才使用持久化批次；旧面板不会获得错误的去重保证。

面板先把批次内容和哈希写入数据库，再返回 202。唯一键由节点类型、节点 ID 和批次 ID 组成。相同批次重试返回成功；同一 ID 对应不同流量返回 409 `CONFLICT`。记录顺序不影响身份校验。

队列在一个数据库事务中更新用户额度、流量积分消耗、邀请首次使用奖励和用户/节点日统计，再标记批次完成。中途失败全部回滚。处理后的原始内容清除，紧凑的批次 ID 和哈希记录长期保留，防止迟到重试再次入账。日统计和倍率使用首次接收时的日期及倍率。用户日统计每 500 条批量增量写入。

每分钟运行 `traffic:process-batches`，最多处理 100 个待处理批次，恢复队列不可用、任务超时等留下的工作。流量重置锁生效时暂缓入账，恢复后继续处理。积压可查询 `v2_node_traffic_batch` 中 `processed_at IS NULL` 的记录；不要手动删除待处理内容或去重凭据。

节点先同步写入待确认文件，再发送；收到明确的 accepted 确认才删除。重载和进程重启后继续补报原 ID 和原内容，每次最多补报 16 批。不同面板地址及节点 ID 分开保存。面板降级后有待确认批次时暂停上报，防止以旧接口重放而重复计费。

默认目录 `/var/lib/v2box/traffic`，可在本地 Nodes 配置中设置 `TrafficSpoolDirectory`，服务运行用户需有写权限。每个节点目录文件总量限制 64 MiB。达到上限或写入失败时，新增计数保留在内存并记录错误；已有批次仍尝试补报。应保证磁盘可用，不要把目录放到临时文件系统。

升级顺序：先升级面板并运行数据库迁移、重启队列和调度，再升级 V2Box。使用 update.sh 可执行面板迁移和任务重启。旧节点无需同时升级。

边界：已成功持久化的批次可在重启后恢复；尚未到上报周期的内存计数、磁盘写入失败后留在内存的计数，无法保证进程崩溃后恢复。首次启动仍要求面板可访问。批次记录长期增长，需要监控数据库容量；当前不自动过期，以保持迟到补报的去重保证。

验证：`php tests/node-traffic-batches.php`、`php tests/node-traffic-concurrency.php`，以及 V2Box API 的 traffic spool 测试。并发测试使用独立进程和本地测试数据库。
