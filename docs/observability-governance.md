# 性能、告警与功能维护入口

## 运维入口

后台「概览 → 系统监控 → 性能与告警」统一查看请求耗时、慢查询数量、健康检查、队列积压、失败任务及前端构建体积。「监控设置」维护采样和阈值。告警仅在后台显示，不发送邮件或其他外部通知。

现有定时任务每分钟执行 `system:monitor`，连续两次异常进入告警，连续两次正常恢复，同一分钟重复检查不累计确认次数；恢复记录保留 24 小时。检查间隔超过 3 分钟会中断连续确认，页面显示过期状态。手工执行命令返回 0 表示无触发中的告警，1 表示存在告警，2 表示检查不可用。沿用现有 cron 和共享缓存，无新增迁移或外部服务。

请求默认抽样 10%，慢请求阈值 2000ms，慢查询阈值 200ms；汇总最近 15 个分钟桶，缓存约一小时。错误率默认 5%、慢请求比例 20%，至少 20 个样本才判断请求类告警。采样为 0 停止请求指标采集，系统与队列检查继续。阈值变更后请求样本重新累计，历史缓存自然过期。

请求只保存接口模板、方法、状态分类和耗时计数，不保存 SQL、绑定参数、IP、用户身份、请求体或实际 URL。慢查询按所属接口排查，不替代数据库自身的慢查询分析；当前不采集后台队列任务内部 SQL。P95 显示直方图桶上界，是估计值。每分钟最多 128 个独立接口，其余归入 OTHER ROUTES；最多展示 50 项。锁竞争时放弃样本并计数，缓存异常不阻断业务。多实例必须共用同一缓存，才能汇总全站数据；缓存重启会丢失短期指标。

队列阈值默认等待 100 个任务或预计等待 60 秒，失败任务默认 1 个；失败数量是 Horizon 的保留窗口总数，并非新增失败速率。恢复以窗口内故障消失为准。监控依赖当前应用和缓存，整站不可访问时无法在后台实时查看。

`npm run build` 生成 `public/console/build-metrics.json`，独立前端包也携带报告。统计全部可达资源体积，以及入口、直接动态启动模块和它们静态依赖的 gzip 体积；后续按需加载页面不计入启动外壳。用户端预算 300 KiB、管理端 450 KiB，超出时构建日志及后台显示警告，不中断发布。gzip 为估算，不代表实际网络耗时。预算与口径维护于 `frontend/scripts/build-metrics.mjs`。

## 唯一维护入口

| 内容 | 后台入口 / 实现 | 边界 |
| --- | --- | --- |
| 节点国家与地区 | 字典维护 / NodeDictionary | 节点展示代码与翻译，不修改 GeoIP |
| IP 地理识别 | GeoIP 数据与服务配置 | 与节点字典独立 |
| 客户端名称、识别别名 | 字典维护 → 第三方客户端 / ClientRecognition | 仅展示识别，不授予访问权限 |
| 客户端启用、最低版本 | 客户端策略 / ClientStrategyService | 不再写入展示名称；保留旧名称作为兼容回退 |
| 客户端安装包、下载地址 | 下载与镜像配置 | 不由识别别名推导 |
| 浏览器访问策略及引导 | 浏览器策略 | 独立于客户端订阅鉴权 |
| 用户行为、访问与转化 | 对应统计报表 / OperationsAnalytics | 产品运营统计，不作为服务性能计数 |
| 日志保留与隐私 | 日志设置 / LogRetentionService | 不同于短期内存性能样本 |
| 性能采样及告警阈值 | 系统监控 → 监控设置 / ObservabilitySettings | 复用 RiskSetting 存储独立前缀 |
| 发布、迁移与队列重启 | 根目录 update.sh | 当前部署依据 |

## 本次治理结果

- 系统监控移除重复的状态、队列原始字段卡片，统一读取定时监控快照；详细队列进程按需加载。兼容 API 暂保留，避免破坏现有外部使用。
- 删除 DashboardUsage 无消费方的 `mixed_timezone` 历史提示字段及其额外查询，并切换汇总缓存版本。保留真实流量汇总。
- 客户端策略接口拒绝修改 `client_name`，提示转到字典维护，避免两个后台入口相互覆盖。兼容存储字段与已有名称不删除。
- 文档分为当前维护入口与历史验证记录；历史框架升级和安全检查记录保留为审计依据，不用作当前部署指令。未因名称相似删除仍有独立统计口径的报表。

后续新增配置、统计或字典时先确认此表是否已有归属；新增指标须说明消费页面、采集开销、保留周期与故障时行为。

节点访问目标统计为独立、默认关闭的可选功能；后台入口、缓存窗口、容量和节点升级要求见 [V2Box](v2box.md#可选的节点访问目标统计)。使用现有 RiskSetting 和缓存，无新增定时任务或逐条数据库访问日志，计费不依赖统计成功。关闭及重新开启使用不同版本，防止积压批次写回新报表。
