# Azure 套餐自动翻译

在服务器 .env 设置 AZURE_TRANSLATOR_KEY、AZURE_TRANSLATOR_REGION，默认端点 https://api.cognitive.microsofttranslator.com。自定义 Azure 资源端点应包含 /translator/text/v3.0（不包含 /translate）。运行 php artisan config:cache。

后台「套餐管理 → 套餐翻译」选择套餐；修改基准名称或说明并保存后，也会原位进入翻译检查。基准语言固定为简体中文，直接使用套餐原文，不再生成或读取同语言副本。名称默认留空并沿用原名；仅明确勾选「翻译套餐名称」时发送名称。其他已支持的内容语言逐一处理，确认后仅把所选名称或描述发送给 Azure，不发送用户信息、价格或账户数据。JSON 只翻译 feature，support 和其他字段保持不变；HTML 使用 Azure HTML 模式。数字变化时拒绝译文，空原文不调用外部服务。

名称和说明分别显示「沿用原文 / 缺失 / 已同步 / 原文已更新 / 历史译文待核对」及来源。默认选择缺失说明和过期机器说明；人工及历史译文必须主动勾选后才生成候选。旧文保留供对照，候选可逐项编辑、选择和批量保存，修改过的候选记为人工译文。手动编辑只保存变更字段；「确认现有译文仍适用」用于明确核对后保留原译文。自动候选和手动编辑互相保护，切换套餐、语言、离页或丢弃时保留未保存确认。

部署前运行新增的套餐翻译版本迁移，为 v2_plan_translation 增加字段级原文指纹和机器/人工来源。安装与升级 SQL 同步列定义，迁移不改写历史译文或假定其已经核对。历史无版本译文继续兼容展示，下一次变更相应原文时记录旧指纹并使其过期；用户读取跳过已知过期字段，依次使用有效回退语言或最新原文，GET 不写回数据。基准语言历史副本保留在库中但不参与展示。密钥只在服务端使用，不进入前端构建；部署、读取、保存套餐本身不会自动调用外部翻译或计费。

保存译文在同一事务内锁定套餐和目标语言，核对选中字段的原文指纹及目标译文版本。生成中再次修改原文、同秒人工编辑和多个管理员操作均不能被旧候选覆盖；冲突停止批次并保留候选供复制核对，重新生成前明确放弃旧候选。仅修改价格、设备数或其他业务字段不会使文本翻译过期。

生成和保存按语言隔离普通错误，重试跳过已完成候选；429 尊重 Retry-After 并暂停后续请求，409 停止保存，均不会自动重放写入。部分失败保留其他结果，套餐保存不依赖翻译服务成功。每次浏览器请求设 45 秒超时，Azure 服务端请求上限 35 秒；生成限额容纳一轮全部语言，但仍有限流保护。数字校验支持波斯文、阿拉伯文及全角数字，数字次序变化不会误报，真正数值变化仍拒绝。流程复用现有服务和按语言接口，不引入独立翻译平台或持续后台计费任务。
