# 修复前全栈安全复核（历史证据）

复核日期：2026-10-25。范围为本工作区 FlClash/FastAI 客户端、v2board 前后台、v2box 节点及其锁定依赖。采用源码调用链审查、公开漏洞数据库、现有隔离回归与少量无网络验证。P1/P2 表示修复优先级，不是 CVSS 分数。下方旧审计章节仅供历史追溯，不能覆盖本节的新发现。

结论：存在需要处理的安全问题，客户端特权边界、客户端依赖和节点内网出站应优先修复。没有访问生产服务器、连接真实支付商、操作用户正在运行的客户端或修改业务代码。

## 确认的问题与适用条件

### P1：Windows Helper 接受无认证的特权核心启动请求

位置：`FlClash/services/helper/src/service/hub.rs:395,412,677,743`，`FlClash/services/helper/src/service/windows.rs:176`，`FlClash/core/server.go:180`。

Windows Helper 在 `127.0.0.1:47891` 提供 `/start`、`/stop`、`/logs`，路由没有调用方身份认证。会话 ID 由请求者选择；`/start` 在校验新核心前先释放当前核心，也不要求匹配原会话。随机管道名及核心文件 SHA-256 限制了名称与可执行文件，不能证明请求者可信。Windows 服务默认使用 LocalSystem；核心随后连接请求者指定的合法格式命名管道，IPC 不验证服务器身份。

已运行现有 `start_releases_the_managed_core_before_rejecting_an_unverified_core` 测试：匿名请求用另一会话 ID 成功释放模拟核心，随后才因不存在的验证目标返回错误。测试未启动真实 Helper 服务。

已确认本地未授权抢占/断连，且存在将 SYSTEM 核心控制权交给本地进程的攻击面；本轮没有尝试任意代码执行或实际提权。建议使用有访问控制的本地 IPC，验证调用者 SID/进程身份，限制核心控制与配置权限，并在变更当前会话前完成全部授权和新实例校验。Linux 的 Unix socket 已另有 UID 检查，不应将 Windows 结论直接套用于 Linux。

### P1（安装条件相关）：Windows 服务可注册到用户可写目录

位置：`FlClash/services/helper/src/service/windows.rs:158`、`FlClash/lib/common/system.dart:311`。

安装器将 `current_exe()` 直接注册为自动启动的 LocalSystem 服务，没有验证安装路径、父目录 ACL 或将 Helper 固定复制到受保护目录。若用户从下载目录或其他可写的便携版目录批准一次安装，后续替换该路径中的 Helper 会形成持久提权风险。核心 SHA-256 校验并不校验服务自身。

这是源码确认的条件性风险；没有检查当前机器已安装服务的目录 ACL，也未覆盖服务文件。建议仅允许受保护的安装目录，校验所有相关父目录及文件权限；便携版应先安装受保护的服务副本。

### P2：Android 快捷操作入口缺少调用方保护

位置：`FlClash/android/app/src/main/AndroidManifest.xml:69`、`FlClash/android/app/src/main/kotlin/ws/fastdog/fastai/QuickActionActivity.kt:14`。

`QuickActionActivity` 显式导出且没有权限约束；收到 START、STOP、TOGGLE 后直接调用服务状态机，没有调用者校验或确认。具备启动 Activity 条件的其他应用可显式调用此入口，停止或切换用户 VPN。是否发生停隧道后的直连还取决于 Android 始终开启 VPN/阻止无 VPN 连接设置，不能直接宣称全部流量必然泄露。

这是源码和 Android 组件语义确认的问题，未在实体设备复现。应保留合法桌面快捷方式能力，同时以不可变 PendingIntent、内部组件或明确用户授权来约束敏感操作，不能只改 action 名称。原有广播接收器的签名权限不保护这个 Activity。

### P1/P2：客户端 Go 与 Rust 依赖未同步安全修复

`FlClash/core/go.mod` 仍包含 x/net 0.57.0、x/crypto 0.54.0、gRPC 1.79.1。按 Windows 实际构建标签、使用 Go 1.27.3 的 govulncheck 源码模式报告 10 项静态可达告警，涉及三个模块；另有各 5 项仅导入包或仅模块级告警。静态路径并不等于已复现利用。

源码模式使用较新的分析工具链，因此还需单独检查实际产物：本地 `FastAICore.exe` 元数据显示 Go 1.25.7，发布 CI 固定 Go 1.26.4。二进制模式报告 57 项包含受影响符号的公告；该数量不能解释为 57 个实际可攻击入口。具体包括 HTTP/2 资源耗尽/竞态和证书信任修复。

建议将构建与发布工具链至少同步到已修复的 Go 1.27.3；x/net 至少 0.60.0、x/crypto 至少 0.56.0，gRPC 同步到覆盖本轮公告的安全版本，并重新编译、测试和发布。只更新本机 Go 或 go.mod 不会修复既有安装包。

Rust 两份 Cargo.lock 共查询 298 个登记项。Helper 的 bytes 1.9.0、h2 0.3.26、anyhow 1.0.93、rand 0.8.5、tokio 1.41.1，以及 Rust API 的 anyhow 1.0.75、tokio 1.34.0 命中公告；adler 1.0.2 另有停止维护提示。合并 GHSA/RUSTSEC 别名后是六类安全/unsound 公告及一项停止维护提示，不是十四个独立漏洞。

其中 h2 的无界空 DATA 帧队列属于拒绝服务问题，公告修复版本为 0.4.16；bytes 的溢出修复版本为 1.11.1。Tokio 广播及 AsyncFd、anyhow downcast、rand 自定义日志的影响取决于相关 API 和输入是否可达，不能仅凭锁文件认定可远程利用。升级 h2 涉及 Warp/Hyper 兼容迁移，应统一升级和回归，不能把 0.4.x 强行覆盖到依赖 0.3.x 的代码。

### P1（公开代理部署）：节点默认允许访问本机、内网和元数据地址

位置：`v2box/core/routes.go:37,165`、`v2box/core/native.go:53`。

默认规则为空且最终直连，没有默认拒绝回环、RFC1918、链路本地、IPv6 本地地址的出站策略。拥有有效节点用户凭据的人可以经代理访问节点能到达的本机/内网服务。这不是匿名认证绕过；若部署用途明确包括私网代理，也须为相应账户和网络建立明确授权边界。

现有 `TestProtocolConnectionsAndAccounting/vless` 已在一次性容器实际通过，使用默认节点配置连接测试创建的 `127.0.0.1` 服务。没有扫描真实内网或请求云元数据。若启用 `PprofPort`，仅监听 127.0.0.1 也不足以与代理用户隔离；同理适用于仅靠回环绑定保护的数据库或管理服务。

建议面向公网代理用户默认拒绝非公网、元数据和管理网段，覆盖 IPv4、IPv6、域名解析后的地址及 UDP；管理/中转出口用明确白名单放行，防火墙与进程网络权限作为第二层约束。sing-box 的 `ip_is_private` 可以作为规则组成部分，但仍需核验解析后规则顺序和元数据等特殊地址。

### P2（渠道启用条件相关）：遗留支付适配器缺少完整结算校验

位置：`v2board/app/Services/Actions/Guest/PaymentActions.php:60`、`v2board/app/Payments/MGate.php:86`，以及 AlipayF2F、WechatPayNative、旧 Stripe 适配器。

共享结算层仅对明确列出的渠道或返回了 `amount` 的适配器强制比较金额与币种。MGate 只返回订单号、回调号；AlipayF2F/WechatPayNative 也未向共享层传递完整金额币种。旧 Stripe 实时换汇与订单结算快照仍未形成统一契约。

使用虚构密钥、无网络容器验证：MGate 对已正确签名但金额为 1、以及没有金额/商户字段的测试参数均返回成功结构，且没有 amount/currency，因而不会触发共享金额校验。本轮未执行订单入账。这不证明攻击者能伪造支付商签名；可利用性取决于渠道启用、网关行为和有效签名事件来源。

旧记录称这些渠道未启用，本轮未连接生产数据库确认现状。已有 EPay、Paytaro、PaytaroQR、StripeCheckout 的强制金额路径仍保留。建议在逐渠道完成已结算事件、订单归属、金额、币种和商户验证前保持遗留渠道停用。

### 已复现并修复

#### 佣金划转并发不一致

`UserActions::transfer` 原先在事务外读取用户余额。两个请求同时使用同一份佣金余额时都返回成功，生成两条划转记录，但余额只增加一次；与其他余额更新并发时还存在覆盖新余额的风险。

修复：在带重试的数据库事务中锁定用户行，读取并校验最新佣金余额，原子保存用户及划转记录。

验证：修复前两个请求均成功且有两条记录；修复后仅一个成功，另一个返回 409，只产生一条记录。另模拟同时入账 500 分，划转 1000 分后余额为 1500 分，佣金为零。

#### 负数套餐价格被视为免费订单

后台八种套餐价格字段原先允许负整数，下单未拒绝负价，结账把所有非正数都作为免费订单处理。触发前提是管理员配置或历史数据含负价；不是普通用户能够直接修改服务端套餐价格。

修复：后台价格最小值为零，下单拒绝未配置或负价周期，结账拒绝历史负数订单。明确设置为零的合法免费订单仍可支付。

验证：八种价格分别测试负数、null、零和正数；负价无法创建订单，历史负数订单不能转为已支付，零元订单仍进入支付处理。

#### Telegram 回调在未配置令牌时认证不安全

原逻辑直接计算配置令牌的摘要，空令牌产生可预测的校验值；此外停用机器人并不拒绝回调。验证了构造回调处理器时认证被接受，未执行伪造消息或向 Telegram 发送请求。具体业务影响还取决于保留的绑定信息和可触发命令。

修复：机器人必须启用且令牌非空，之后才比较回调凭据。V10 继续使用请求头，旧入口继续使用原参数，不改变已配置机器人的签名协议。

## 保留旧接口的鉴权与敏感字段复核

- 管理员 `user/fetch`、`user/getUserInfoById` 原先直接序列化整行用户，包含密码哈希、密码算法/盐、原始订阅 token 和 UUID；详情的 `invite_user` 也返回整行邀请人。这些接口已受管理员鉴权保护，本轮没有复现匿名或员工越权访问，但敏感字段的过度返回成立。现在改用显式字段白名单，邀请人仅投影 ID/邮箱；`User` 默认隐藏密码材料，提供额外的序列化保护。

## V10 认证、资源归属与响应字段复核

发现并修复浏览器注册的凭据暴露：实际入口为 `POST /api/v10/auth/registrations`，`BrowserSession` 的成功登录接入名单却使用不存在的 `/api/v10/auth/accounts`。因此浏览器注册响应会保留原生 `accessToken`，没有转换为 HttpOnly Cookie 会话状态。现在使用实际注册路径；浏览器响应只含账户 ID、认证状态、CSRF 和过期时间，注册时轮换 HttpOnly Cookie。原生注册继续返回有效 Bearer JWT；原生与浏览器的兼容合同不变。这是注册者自身的 JWT 暴露给前端 JavaScript，不是已证实的跨账户数据读取。

同时统一认证用户资源的 `private, no-store`，覆盖先前遗漏的精确 `/me` 路径及 `/plans`、`/payment-methods`、`/knowledge-articles` 等位于 `/me/*` 之外的账户相关资源；已有 Cookie、认证、订阅响应仍禁止存储。此前这些资源并非允许公开缓存，本次属于更严格的敏感响应缓存策略。

未复现同类匿名鉴权绕过或跨用户 IDOR。验证包括：

- 64 个 V10 用户入口，逐入口测试缺失认证、数组查询凭据、JSON 数组凭据及伪造 Bearer，共 256 次认证拒绝；与保留接口检查合计 1,831 项路由断言。
- 两个独立用户间的订单详情/状态/支付/取消、工单详情/回复/关闭/已读回执返回 404，伪造查询和请求体中的用户/角色字段不能改变归属；拒绝后订单、工单与消息保持不变。
- 外来会话 ID 不能撤销另一账户会话；账户资料更新不能注入角色、密码或订阅凭据；账户与订阅响应不能通过伪造用户 ID 返回另一账户的密码材料、token 或 UUID。
- 普通账户的有效 JWT 不能访问任何 V10 节点机器入口（包含独立上报凭据的地址入口）；节点共享密钥、订阅 token、账户 JWT 是不同认证边界。
- 浏览器注册必须通过 CSRF 与精确 Origin 校验；注册响应不含 JWT，Cookie 可认证新账户；原生注册仍可取得有效 Bearer。MFA 和一次性授权码的原有认证/撤销规则继续通过回归。

## V2Box 单实例多后台隔离

单进程现在为每个后台/节点身份独立管理控制器、核心、准备期限、退避和回滚。启动时不可用的后台不会阻止其他条目就绪；节点轮询只唤醒自身的重载。配置文件条目增加、删除和重排按身份处理，取消与重新加入同一身份会等待原所有者释放资源，避免旧清理覆盖新实例。不同后台可以复用节点/用户/物理服务器 ID；统计和队列按原节点作用域保存，同后台相同物理服务器配额仍共同累加，不跨后台共享。显式重复身份或共享证书/私钥路径被拒绝。

默认证书、账户和 ACME 保护状态按后台及节点分目录；旧有效且身份匹配的默认证书复制到新目录，旧文件保留，暂停或中断签发的保护状态不能因迁移被绕过。ACME 进程环境及等待也按证书身份隔离。后台部署帮助程序的就绪检查兼容新目录、自定义目录和旧文件。

IP 上报支持最多 64 个目标、最多 8 个并发任务，各自保留 401 暂停、429/临时网络退避和配置指纹。追加或轮换一个目标不会覆盖其他后台和直接 DNS 目标。全局 disable 仍停止全部调度。随后一键部署也已按后台与节点身份支持自动追加，详见下节；错误身份和不兼容程序仍会被拒绝。

新增回环测试验证另一后台已建立的代理长连接在单节点恢复、重载和端口冲突回滚期间保持传输。还验证后台间凭据边界、节点移除/重排、配额作用域、证书占用和迁移、IP 上报并发及独立重试。节点脚本 55 项、部署帮助程序 57 项通过；完整 Go race、静态检查、构建及二进制验证结果保存于 storage/app/test-organization/security-fixes/node-multipanel-*。本轮没有生产部署或公网证书申请。

进程级更新、重启、崩溃仍影响全部节点，全局出站策略/日志设置也适用于全部条目。这是单进程内的节点故障隔离；不承诺隔离进程或主机故障。当前每条目独立取消，保留退出超时 30 秒的进程恢复兜底，替代之前整组重载超时后退出的处理方式。


## 多后台一键部署

一键部署按后台/节点身份原子合并 Nodes，不覆盖其他节点、证书及全局自定义设置。已有兼容运行实例通过 SIGHUP 局部应用，服务停止时才启动；旧运行进程或上报脚本缺少能力、运行中程序文件缺失时在兑换授权前拒绝，避免另一后台引发全局升级/重启。安装与恢复入口固定 v1.0.12，匹配的发行包发布是上线前置；本轮没有发布安装包或修改生产服务。

节点与上报恢复状态按目标分别保存，旧状态文件可恢复，执行锁避免并发写配置。成功完成回执仅保存授权哈希、身份和凭据指纹，权限 600；同一成功命令重放不再次消耗授权，凭据变化时旧回执不能覆盖当前配置。新节点在 IP、DNS 和验证端口检查前只保留私有授权，不提前进入活动 Nodes。回滚只删除本次新增且未被修改的条目，不覆盖其他后台或管理员后续修改。

上报绑定按后台分别保存；不同后台可复用服务器 ID，同后台错误服务器绑定仍拒绝。实际多目标上报模块保留直接 DNS 目标、其他后台凭据和独立退避。临时报告密钥、授权文件均在退出时清理，私有快照与完成记录不输出凭据。

验证覆盖后台全部测试入口、前端全量测试/类型检查/构建、节点全包 race/vet/构建与完整脚本测试。真实节点二进制与两个本地 HTTPS 后台验证了一键追加相同节点 ID，原代理长连接、已有证书及 IP/DNS 目标保留，--watch=false 下 SIGHUP 生效，重复原命令只兑换一次且无重启。结果位于 storage/app/test-organization/oneclick-multipanel/；未调用公网 ACME 或生产 DNS 凭据。
