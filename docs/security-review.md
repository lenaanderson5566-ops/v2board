### 已复现并修复

#### 佣金划转并发不一致

`UserActions::transfer` 原先在事务外读取用户余额。两个请求同时使用同一份佣金余额时都返回成功，生成两条划转记录，但余额只增加一次；与其他余额更新并发时还存在覆盖新余额的风险。

修复：在带重试的数据库事务中锁定用户行，读取并校验最新佣金余额，原子保存用户及划转记录。

验证：修复前两个请求均成功且有两条记录；修复后仅一个成功，另一个返回 409，只产生一条记录。另模拟同时入账 500 分，划转 1000 分后余额为 1500 分，佣金为零。

#### 负数套餐价格被视为免费订单

后台八种套餐价格字段原先允许负整数，下单未拒绝负价，结账把所有非正数都作为免费订单处理。触发前提是管理员配置或历史数据含负价；不是普通用户能够直接修改服务端套餐价格。

修复：后台价格最小值为零，下单拒绝未配置或负价周期，结账拒绝历史负数订单。明确设置为零的合法免费订单仍可支付。

验证：八种价格分别测试负数、null、零和正数；负价无法创建订单，历史负数订单不能转为已支付，零元订单仍进入支付处理。

#### Telegram 回调在未配置令牌时认证不安全

原逻辑直接计算配置令牌的摘要，空令牌产生可预测的校验值；此外停用机器人并不拒绝回调。验证了构造回调处理器时认证被接受，未执行伪造消息或向 Telegram 发送请求。具体业务影响还取决于保留的绑定信息和可触发命令。

修复：机器人必须启用且令牌非空，之后才比较回调凭据。V10 继续使用请求头，旧入口继续使用原参数，不改变已配置机器人的签名协议。

## 保留旧接口的鉴权与敏感字段复核

范围包括保留的 13 条用户/认证/公共/客户端路由、配置的管理与运营路径、员工接口、V1/V2 节点入口及自定义订阅共用的认证中间件。检查共享 `AuthService`、浏览器会话、MFA 挑战、订阅凭据与回调认证，并核对用户数据返回路径。

发现并修复：

- 管理员 `user/fetch`、`user/getUserInfoById` 原先直接序列化整行用户，包含密码哈希、密码算法/盐、原始订阅 token 和 UUID；详情的 `invite_user` 也返回整行邀请人。这些接口已受管理员鉴权保护，本轮没有复现匿名或员工越权访问，但敏感字段的过度返回成立。现在改用显式字段白名单，邀请人仅投影 ID/邮箱；`User` 默认隐藏密码材料，提供额外的序列化保护。
- 旧 `user` 中间件仍接受 URL 中的 JWT，且查询参数可优先于请求头；这不绕过 JWT 验证，但会把有效凭据暴露给 URL 记录链路。现在与管理入口统一为请求头优先、兼容 POST JSON/表单凭据，拒绝 URL 凭据。退出动作同步采用这一来源规则。
- 订阅中间件在进入 SQL/缓存处理前增加非空字符串检查，拒绝数组、数字与布尔凭据；固定、一次性和时效订阅模式共用该检查。未发现仅凭伪造数组即可取得订阅的有效证据，此项属于类型边界加固。
- 管理员修改用户密码/邮箱原先不撤销旧会话，与员工修改及找回密码流程不一致。现已统一在保存成功后撤销用户全部旧会话，封禁继续撤销；新增密码和邮箱两种管理操作的回归断言。

验证复用现有测试模块，没有新增独立脚本。8 组隔离回归全部通过：实际 350 条注册路由中，198 条受保护旧路由执行 709 次攻击拒绝探测；路由检查共 1,639 项，另覆盖 64 个 V10 用户认证入口与 V1/V2 节点密钥拒绝。V10 合同 172 项、通用后端安全 96 项、浏览器会话 492 项、节点兼容 750 项及控制台 smoke 均通过；完整登录安全测试含补充退出场景为 59 项，专项安全在补充管理员会话撤销场景后为 60 项，结果记录于 `storage/app/test-organization/legacy-auth-review/`。

边界：管理员复制/CSV 导出的订阅链接仍按既有管理功能返回；成功的原生登录返回本人的登录/订阅凭据，已认证节点获取其服务用户的连接 UUID。不能把这些协议输出描述为“所有接口都不返回 token”。旧支付回调继续使用共享验签处理，专项回归不替代每个支付渠道的线上验签。没有访问或遍历生产用户、进行生产部署，也不据本轮定向检查声明不存在其他漏洞。

## V10 认证、资源归属与响应字段复核

发现并修复浏览器注册的凭据暴露：实际入口为 `POST /api/v10/auth/registrations`，`BrowserSession` 的成功登录接入名单却使用不存在的 `/api/v10/auth/accounts`。因此浏览器注册响应会保留原生 `accessToken`，没有转换为 HttpOnly Cookie 会话状态。现在使用实际注册路径；浏览器响应只含账户 ID、认证状态、CSRF 和过期时间，注册时轮换 HttpOnly Cookie。原生注册继续返回有效 Bearer JWT；原生与浏览器的兼容合同不变。这是注册者自身的 JWT 暴露给前端 JavaScript，不是已证实的跨账户数据读取。

同时统一认证用户资源的 `private, no-store`，覆盖先前遗漏的精确 `/me` 路径及 `/plans`、`/payment-methods`、`/knowledge-articles` 等位于 `/me/*` 之外的账户相关资源；已有 Cookie、认证、订阅响应仍禁止存储。此前这些资源并非允许公开缓存，本次属于更严格的敏感响应缓存策略。

未复现同类匿名鉴权绕过或跨用户 IDOR。验证包括：

- 64 个 V10 用户入口，逐入口测试缺失认证、数组查询凭据、JSON 数组凭据及伪造 Bearer，共 256 次认证拒绝；与保留接口检查合计 1,831 项路由断言。
- 两个独立用户间的订单详情/状态/支付/取消、工单详情/回复/关闭/已读回执返回 404，伪造查询和请求体中的用户/角色字段不能改变归属；拒绝后订单、工单与消息保持不变。
- 外来会话 ID 不能撤销另一账户会话；账户资料更新不能注入角色、密码或订阅凭据；账户与订阅响应不能通过伪造用户 ID 返回另一账户的密码材料、token 或 UUID。
- 普通账户的有效 JWT 不能访问任何 V10 节点机器入口（包含独立上报凭据的地址入口）；节点共享密钥、订阅 token、账户 JWT 是不同认证边界。
- 浏览器注册必须通过 CSRF 与精确 Origin 校验；注册响应不含 JWT，Cookie 可认证新账户；原生注册仍可取得有效 Bearer。MFA 和一次性授权码的原有认证/撤销规则继续通过回归。

隔离验证：api-route-audit 1,831 项、api-v10 198 项、api-v10-inventory 846 项、browser-session 499 项、MFA 57 项、node-v10 45 项、session-authorization 18 项及 coupon-availability 均通过。首轮 inventory 新增断言错误假设所有自定义端点都有 `status`；改为检查文档中实际成功响应后，inventory 与最终 V10 合同定向复跑通过。前端 V10 传输/认证 37 项及 TypeScript 通过。复用原测试模块，结果在 `storage/app/test-organization/v10-security-review/`；没有新建独立脚本或部署生产。

敏感字段边界仍以业务授权为准：本人订阅配置/教程可以包含本人的连接凭据，具备有效订阅资格的下载账户接口按功能返回共享下载账户密码，受节点密钥保护的机器接口返回连接 UUID；不能把这些必要输出归类为匿名泄露。本轮属于源码审查与定向回归，没有穷举第三方支付、邮件服务或真实外部系统的所有攻击面。

## 工单文本与图片边界

当前工单只有文本消息，没有工单图片上传、附件保存或附件下载接口；前端使用 React 文本节点显示消息，不解析 HTML/Markdown 图片。新增 img onerror 与 svg onload 文本回归，确认工单消息内不会生成这些 DOM 元素。管理员回复限制为字符串，最长 10000 字符。此结论限于当前工单链路，不代表其他上传功能已获同等审计。

若未来提供截图上传，应采用 JPEG/PNG/WebP 白名单、服务端解码重编码、大小与像素限制、随机文件名、非执行目录存储，以及工单所有者/管理员访问鉴权；不直接支持 SVG/HTML，不信任浏览器 MIME 或文件后缀。响应固定正确 Content-Type 并设置 nosniff，避免将原始文件作为同域活动文档展示，同时处理限流和配额。参见 [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

自动关闭仍为管理员最后回复满 24 小时且无用户追问；调度对每条候选在事务和行锁内重新读取状态及最后一条消息，回复使用同一锁，避免调度旧快照覆盖新回复。最后回复用户从消息表查询，不依赖不存在的 last_reply_user_id 属性。
