# 用户导航与订阅支付流程

用户端订单记录统一显示为“账单”。侧栏和手机底栏按账户状态调整，详见 [用户导航与快速开始](user-setup-navigation.md)。头像菜单保留账户设置、通知设置、账户安全、邀请好友与退出；流量记录从使用分析进入，原页面地址继续可用。

订阅按三个阶段呈现：选择套餐、确认与支付、开通完成。套餐卡片显示实际存在的第一个购买周期及其价格，支持季付、半年付、零元周期和一次性套餐。普通购买不混入流量重置；有效订阅可单独购买重置，并明确不会延长有效期。有效期内可续费的隐藏套餐保留入口。

套餐目录进入统一结算页，在同一页选择周期、个人券包优惠和支付方式；服务端预报价列出优惠、折抵、余额抵扣、渠道费用及最终支付币种。预报价不会创建订单或占用资产，用户确认后再校验并创建订单、发起支付。已有状态0或1订单时引导继续该订单，避免再次创建被服务端拒绝。创建失败保留输入并提供账单入口。

付款页展示后端订单的应付、优惠、折抵、余额抵扣及退回余额信息。已确认渠道复用下单时保存的报价快照；其他渠道使用服务端报价。发起支付时校验预期金额及币种，变化时重新确认。无可用方式时禁止发起收费支付；零应付订单可直接确认开通。信用卡提交前也显示金额。

支付发起后优先检查状态，可显式重新发起；5秒检查一次，连续定时检查最多60次，页面隐藏时不发送检查请求，回到页面或手动点击可再次检查。网关返回成功并不直接显示开通完成：状态1表示支付已确认、等待开通，状态3才显示完成。二维码在订单离开待支付状态后清除，完成后的订阅导向总览导入配置，充值导向账户余额。

取消需要确认，并说明余额返还及已付款时先检查结果。支付错误直接显示，信用卡失败关闭弹窗以避免错误藏在弹窗后。手机页面采用单列与固定确认区域。

订单后台刷新时保留付款界面，不重新挂载支付组件，避免语言切换或刷新时丢失已选方式、二维码和信用卡输入。

设计参考 [W3C WCAG 3.3.4 交易信息复核与确认](https://www.w3.org/WAI/WCAG22/Understanding/error-prevention-legal-financial-data.html)。预报价和下单共用 Laravel 计价准备逻辑；现有订单状态及支付适配器保持不变，无需数据库结构迁移。

前端测试使用模拟网关，不发起真实扣款。静态资源随仓库发布，真实支付回调及生产队列开通仍需在部署环境验收。
