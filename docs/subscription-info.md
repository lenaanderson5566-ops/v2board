# Supplementary subscription information

Public subscriptions, configured custom subscription paths and application-config retain node-name notices. After a valid subscription credential is checked, an unavailable entitlement, banned account, disabled known client or outdated client receives HTTP 200 in the requested public format with a localized warning node. An empty node list also receives a notice for template-free list formats, including lists that become empty after the selected format filters unsupported protocols. Entitled full-template formats may intentionally supply static or provider nodes and retain their existing behavior. FastAI native configuration keeps its structured errors: 403 for unavailable entitlement or disabled client, and 409 for an unsupported client version. A subscription failure does not revoke the account session.

Warning documents are generated only by the closed `SubscriptionNotice` renderer. It cannot accept an account or node list, and never loads a default/custom configuration template. The only proxy is the documentation address `203.0.113.10:61001` with fixed dummy credentials, never the account UUID/token. The documents contain no real proxy, remote provider or external rule URL. YAML/INI notice rules reject traffic; sing-box and URI/proxy-list notices select only the inert documentation endpoint. Replies use `private, no-store` and an `X-Subscription-Notice` reason header. Protocol metadata left by a discarded normal render must be cleared before returning a notice or an error.

SIP008 notices omit the optional `bytes_used` and `bytes_remaining` metadata, so they do not present fabricated account usage or quota. Those fields describe real byte counts in the [SIP008 specification](https://github.com/shadowsocks/shadowsocks-org/wiki/SIP008-Online-Configuration-Delivery). This does not claim that a particular client hides or displays a zero-quota profile in a specific way.

Reasons distinguish no plan, expired plan, exhausted plan allowance, expired/exhausted independent credits, no available nodes, a disabled/outdated client, an account ban and a subscription change during rendering; unclassified unavailable profiles retain the generic notice. All fourteen subscription languages use the same reason keys. These HTTP 200 documents explain the problem; they do not authorize real proxy access.

Invalid or rotated subscription credentials, deleted accounts, unknown user agents, blocked requests and rate limits continue to fail with their existing hard errors. The account read at the token boundary is checked again before rendering, and the final account/UUID/token/effective-group check discards a configuration that became unauthorized during rendering. An entitlement or group change returns a fresh safe public notice; credential rotation/deletion remains a hard rejection. No normal custom-template contents are reused for these responses.

Valid independent credits intentionally permit access after a periodic plan expires, within the effective credit group. Public route previews retain an explicit display-only field list without connection credentials. Previously downloaded files cannot be erased by a server-side download check; node user-list synchronization remains responsible for actual connection authorization. The checks use current account and batch validity, not the timing of the expiry cleanup job, and add no schema migration.

The existing `show_info_to_server_enable` setting controls one concise output format. Supported third-party node lists show the next automatic plan reset, remaining independent traffic and unexpired reset-credit counts. The reset date uses UserService's shared schedule and application timezone, displayed as MM-DD HH:mm with a compact GMT offset (for example GMT+8 or GMT+5:45); it is omitted when no reset is scheduled before plan expiry. Independent traffic and reset credits are omitted when zero. The balance uses the User credit accessor, which deducts expired traffic batches; reset counts use UsageResetService's available-credit query. Standard subscription traffic/expiry headers are unchanged and retain their existing combined-quota semantics. No additional plan expiry or remaining-total placeholder is inserted.

Fourteen-language copy follows subscription language negotiation. Surge and Surfboard's `$subscribe_info` template slot uses the same supplementary lines. Normal sing-box configurations omit these supplementary nodes; their unavailable notices use the separate closed renderer described above. FastAI native configuration generation never adds these lines and also removes them from custom templates.

The count represents owned, unexpired reset credits, not a command to reset usage or a guarantee that resetting is currently allowed. Actual consumption remains on the website and follows existing eligibility checks. Third-party clients receive a snapshot when updating their subscription. Independent traffic-batch expiration details remain on the website.

Verification reuses `tests/credit-expiry.php`, `tests/credit-access.php`, `tests/subscription-client-policy.php`, `tests/api-v10.php`, `tests/subscription-info.php`, `tests/client-import-language.php`, `tests/fastai-template.php` and `tests/fastai-client-config.php`. Coverage includes every public notice format, localized names, template/provider exclusion, exact expiry, consumed credits, stale account/render snapshots and the hard credential boundaries. Parser and safety assertions are not a claim that every third-party application or native proxy engine has been exercised. No database migration or App rebuild is required.
