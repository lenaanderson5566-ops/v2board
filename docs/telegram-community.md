# Telegram 绑定与群资格管理

## 更新与启用

本次功能默认关闭，避免升级时直接清退现有群成员。`update.sh` 已纳入 `2026_10_13_000005_add_telegram_membership.php`；独立部署须先执行该迁移，再发布应用代码。新安装的 `database/install.sql` 同样包含两张新表。

1. 建议使用私有超级群。添加机器人并授予管理员、邀请成员、限制成员权限。
2. 后台「设置 → Telegram」保存机器人 Token、负数群 ID，宽限天数默认 **3 天**，可设为 0–30。
3. 点击「检查机器人权限」，再「设置 Telegram Webhook」。注册会显式订阅 `chat_member` 和 `chat_join_request`。Webhook 地址必须为公开 HTTPS。
4. 核查历史成员后启用「群成员资格管理」。撤销旧的免审核邀请链接，避免其他管理员绕过申请流程加人。
5. 确保 Laravel scheduler 每分钟运行。`telegram:sync-members` 分批扫描，每批最多 50 个已知成员，正常成员约 5 分钟后再次入队；大群和失败重试会延长实际处理延迟。连续出现 3 次失败则停止本批，避免持续请求故障服务。

## 用户流程

在网站账号设置获取 10 分钟绑定链接 → Telegram 点击 Start → 返回网站刷新 → 核对 Telegram ID/名称并确认。链接仅保存哈希，最终确认要求登录会话和匹配的 Telegram ID，不接受订阅链接作为绑定凭据。重新生成链接会使上一条失效。一个 Telegram 账号只能绑定一个网站账号；历史重复绑定需人工处理。

绑定后可申请 10 分钟有效、需要审核的邀请链接。机器人依据申请人的 Telegram ID 验证资格，转发链接不会使不符合资格的账号获准加入。用户解绑后失去资格。

资格：账号未封禁、有套餐，且套餐有效或到期后仍在宽限期。永久套餐不因时间被清退；流量耗尽不影响群资格。到期时间加 3×24 小时即为默认宽限截止时间，截止后由计划任务清退。

自动清退使用 120 秒短时封禁，期限结束后有资格的用户可重新申请入群，不会自动拉回群。程序不调用自动解封，避免误解除人工封禁；升级前遗留的永久自动封禁须管理员核查后手动解除。人工封禁和结果不确定的封禁交管理员核查。群主、管理员不会自动清退。

## 历史成员与异常处理

Telegram Bot API 不提供遍历全部历史成员的接口。系统收集已绑定账号、成员变动、入群请求、可见消息中的成员 ID；未绑定且不活跃的历史成员需要后台导入 ID 或人工核查。导入只是加入资格检查队列，启用策略后不合格的在群成员会被清退。

后台显示已知成员、待检查数、异常数、上次同步和最近 50 条记录（异常优先）。`TELEGRAM_CHECK_FAILED` 请检查网络和机器人权限；`BAN_REQUIRES_REVIEW` 表示清退请求结果不确定，请在 Telegram 人工核查；`MANUAL_BAN` 表示人工封禁。人工解除封禁后，后续同步会重新检查状态。群管理员的操作与机器人并发时仍可能存在 Telegram 外部状态竞态，重要人工封禁请复查。

只保存绑定账号、Telegram ID/待确认名称、群成员资格状态和有限错误代码；不保存聊天正文、联系人列表或 Telegram 登录凭据。过期绑定挑战由定时任务删除。机器人 API 失败不会向用户返回 Token 或原始异常详情。

## 部署后人工验收（本次未执行真实 Telegram 操作）

- 未绑定、无套餐、已封禁和超出宽限的账号无法通过入群申请。
- 有效套餐、宽限期、永久套餐可以申请；流量耗尽仍可申请。
- 绑定链接过期、重发、Telegram ID 不匹配、重复绑定被拒绝。
- 到期清退、续费重新申请、解绑清退以及管理员豁免符合预期。
- 核查人工封禁没有被自动续费流程解除，故障记录与计划任务监控可见。

## 功能范围与升级

Telegram 保留账号绑定、解绑指引、用户群资格管理，以及管理员支付到账提醒。机器人命令仅有 `/start`、`/bind`、`/unbind`、`/group`；账号查询、流量查询、通知偏好、工单回复、网站地址查询和按钮菜单已移除。网站仅展示绑定状态和经资格审核的入群入口，不再展示旧的直接入群链接。

- 保留管理员支付到账提醒，关闭用户提醒和管理员工单、节点掉线通知。到账提醒只发给已绑定且未封禁的管理员，发送前再次检查身份；使用独立支付通知队列任务，旧的通用通知任务不恢复投递。通知失败不影响支付回调成功确认。支付回调、订单到账、工单和其他渠道功能保持原有流程。
- 移除通知调度和投递服务；`telegram:notify` 保留为空操作以兼容旧的外部 cron，旧 `SendTelegramJob` 消费后不发送消息。
- 已有通知和偏好表保留，不执行破坏性迁移；这些历史记录不再用于发送通知，绑定与解绑不再依赖这些旧表。
- 更新后重启队列工作进程，确保没有旧代码继续运行；然后在后台重新设置 Telegram Webhook，更新机器人命令菜单及事件订阅。无需重新绑定现有账号。
- Webhook 仅订阅 `message`（绑定和成员观察）、`chat_join_request`、`chat_member`、`my_chat_member`。旧按钮回调即使仍到达也不执行操作。

本次仅进行代码检查、PHP 语法检查和前端构建，不向真实 Telegram 群发送消息或执行清退。

## 2026-10-14 安全与可靠性调整

升级执行 `2026_10_14_000001_harden_telegram_delivery.php`（已纳入 update.sh），然后重启队列进程。新安装 SQL 同步包含身份占用、Webhook 收件箱、管理员支付通知三张表。现有重复 Telegram 绑定不被自动合并；资格判断仍拒绝重复身份，管理员需核查归属后解绑重绑。

- 数据库唯一身份占用替代全站缓存锁；账号行锁协调生成链接、确认和解绑。确认仍校验登录用户、挑战有效期和预期 Telegram ID。
- Webhook 只保存所需事件字段，不保存任意聊天正文。绑定命令包含短期令牌，因此收件内容使用应用密钥加密；处理完成立即清除载荷，事件去重记录保留 7 天。
- 正常情况下立即入队，`telegram:process` 每分钟补捞。同步队列配置下 Webhook 只落库，由计划任务处理，可能延迟约一分钟。`send_telegram` 队列必须有工作进程或正常计划任务。
- 每个事件和支付通知通过数据库状态更新独占处理。429 有限重试；网络中断或工作进程中断标记不确定，不自动重复副作用。后台展示计数和有限错误代码，无原始响应、密钥或正文。
- 支付到账通知按订单与管理员唯一去重，发送时重新核对管理员身份、原始账号与 Telegram 绑定及机器人身份。正文按发送时管理员的网站语言生成；保留小型去重记录，不保存通知正文。
- 机器人回复按网站账号语言优先、Telegram language_code 次之、英语兜底；未绑定的绑定命令从有效挑战找到网站语言。支持网站现有八种语言。Telegram 公共命令菜单按其语言代码注册，需要在后台重新设置 Webhook；用户私聊机器人时会按网站语言更新该私聊的菜单（包括繁体中文）。菜单更新失败不会阻断绑定。
- 本地绑定状态查询不再依赖 getMe，username 可为空；生成绑定链接仍要求机器人 API 可用。
- 自动短时清退仍与 Telegram 管理员操作存在外部竞态，API 没有原子条件封禁接口；管理员同时更改封禁时需核查最终状态。群主和管理员继续豁免自动清退。

## 登录、统计与客服接入评估

当前未新增 Telegram 登录、Passkey 或 MFA 入口。优先建议在独立认证改造中加入 Passkey，并为管理员要求 MFA、普通用户可选启用 TOTP 与一次性恢复码。必须统一覆盖密码登录、密码恢复、客户端浏览器授权、会话交换与敏感操作再认证，避免旧登录路径绕过 MFA。Passkey 的 RP ID/Origin 应使用稳定的正式域名；不能把任意前端 Host 或备用入口直接作为受信任来源。Telegram 群绑定不能作为登录证明，未来 Telegram 登录需独立 OIDC 流程和 state/nonce/PKCE、签名/issuer/audience/expiry 校验，并禁止据第三方邮箱自动合并账号。

现有用户前端已有 UsageChart，客户端有本地 line_chart/donut_chart 和默认关闭的自愿诊断上报。此轮用户流量图补充周期上传、下载、总用量和日均值，复用已有数据，不增加追踪。复杂统计可考虑 ECharts（网页）/fl_chart（Flutter）；营销分析可另行评估自托管 Umami，但需路径白名单，不能发送包含订阅或授权凭据的 URL。不开启会话回放、输入采集或全量网络请求采集。

Chatwoot 适用于多客服共享收件箱；不建议把客服脚本加载到管理员页面。前台接入需明确部署地址、Inbox Token 和服务端身份验证密钥，服务端签发身份 HMAC、HTTPS 主机白名单、按需加载、退出/切换账号 reset、跟随网站语言。管理后台仅提供独立工作台链接；不向浏览器下发 Chatwoot 管理员 API Token。按本轮用户要求，暂不接入 Chatwoot；维持现有客服接入，不加载第二套客服 SDK。
