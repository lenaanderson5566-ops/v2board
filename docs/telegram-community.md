# Telegram 绑定与群资格管理

## 更新与启用

本次功能默认关闭，避免升级时直接清退现有群成员。`update.sh` 已纳入 `2026_10_13_000005_add_telegram_membership.php`；独立部署须先执行该迁移，再发布应用代码。新安装的 `database/install.sql` 同样包含两张新表。

1. 建议使用私有超级群。添加机器人并授予管理员、邀请成员、限制成员权限。
2. 后台「设置 → Telegram」保存机器人 Token、负数群 ID，宽限天数默认 **3 天**，可设为 0–30。
3. 点击「检查机器人权限」，再「设置 Telegram Webhook」。注册会显式订阅 `chat_member` 和 `chat_join_request`。Webhook 地址必须为公开 HTTPS。
4. 核查历史成员后启用「群成员资格管理」。撤销旧的免审核邀请链接，避免其他管理员绕过申请流程加人。
5. 确保 Laravel scheduler 每分钟运行。`telegram:sync-members` 分批扫描，每批最多 50 个已知成员，正常成员约 5 分钟后再次入队；大群和失败重试会延长实际处理延迟。连续出现 3 次失败则停止本批，避免持续请求故障服务。

## 用户流程

在网站账号设置获取 10 分钟绑定链接 → Telegram 点击 Start → 返回网站刷新 → 核对 Telegram ID/名称并确认。链接仅保存哈希，最终确认要求登录会话和匹配的 Telegram ID，不接受订阅链接作为绑定凭据。重新生成链接会使上一条失效。一个 Telegram 账号只能绑定一个网站账号；历史重复绑定需人工处理。

绑定后可申请 10 分钟有效、需要审核的邀请链接。机器人依据申请人的 Telegram ID 验证资格，转发链接不会使不符合资格的账号获准加入。用户解绑后失去资格。

资格：账号未封禁、有套餐，且套餐有效或到期后仍在宽限期。永久套餐不因时间被清退；流量耗尽不影响群资格。到期时间加 3×24 小时即为默认宽限截止时间，截止后由计划任务清退。

机器人成功自动清退的账号，在续费恢复资格后解除该次自动封禁，用户需重新申请入群，不会自动拉回群。人工封禁和结果不确定的封禁交管理员核查。群主、管理员不会自动清退。

## 历史成员与异常处理

Telegram Bot API 不提供遍历全部历史成员的接口。系统收集已绑定账号、成员变动、入群请求、可见消息中的成员 ID；未绑定且不活跃的历史成员需要后台导入 ID 或人工核查。导入只是加入资格检查队列，启用策略后不合格的在群成员会被清退。

后台显示已知成员、待检查数、异常数、上次同步和最近 50 条记录（异常优先）。`TELEGRAM_CHECK_FAILED` 请检查网络和机器人权限；`BAN_REQUIRES_REVIEW` 表示清退请求结果不确定，请在 Telegram 人工核查；`MANUAL_BAN` 表示人工封禁。人工解除封禁后，后续同步会重新检查状态。群管理员的操作与机器人并发时仍可能存在 Telegram 外部状态竞态，重要人工封禁请复查。

只保存绑定账号、Telegram ID/待确认名称、群成员资格状态和有限错误代码；不保存聊天正文、联系人列表或 Telegram 登录凭据。过期绑定挑战由定时任务删除。机器人 API 失败不会向用户返回 Token 或原始异常详情。

## 部署后人工验收（本次未执行真实 Telegram 操作）

- 未绑定、无套餐、已封禁和超出宽限的账号无法通过入群申请。
- 有效套餐、宽限期、永久套餐可以申请；流量耗尽仍可申请。
- 绑定链接过期、重发、Telegram ID 不匹配、重复绑定被拒绝。
- 到期清退、续费重新申请、解绑清退以及管理员豁免符合预期。
- 核查人工封禁没有被自动续费流程解除，故障记录与计划任务监控可见。

参考：[Telegram Bot API](https://core.telegram.org/bots/api) 的 `setWebhook`、`ChatJoinRequest`、`banChatMember`、`unbanChatMember`。

## 服务助手与用户通知

此轮将 Telegram 的职责限定为查询、绑定确认、群资格自动管理和自愿订阅的服务提醒。密码修改、订阅凭据重置、自动登录链接、支付操作不进入机器人；解除绑定、用户与管理员回复工单统一在已登录网站办理。`/unbind` 和旧工单回复入口仅给出网站处理提示。

- `/start`、`/help` 打开按钮菜单；`/account` 查询套餐期限；`/traffic` 查询剩余流量；`/group` 查询群资格；`/settings` 设置提醒偏好。
- 套餐、工单、到账通知各自默认关闭，由绑定用户明确开启。免打扰默认开启，按用户展示时区 22:00–08:00（跟随设备的用户使用系统时区；机器人无法读取设备时区），期间延后；账号解绑或换绑清除偏好，必须重新开启。
- 套餐提醒按到期前 3 天内、1 天内分阶段去重；群宽限期开始和剩余 1 天内提醒。实际送达受任务轮次、限流和免打扰影响，不能作为准点或必达承诺；宽限规则仍以网站为准。续费后会取消已经失效的旧到期提醒。
- 到账通知从已经完成权益发放的订单生成，不由收到支付回调直接触发。工单只提醒存在客服回复，不包含正文、主题、用户邮箱、IP、位置或余额。管理员工单通知同样仅保留编号和处理提示。
- `telegram:notify` 每分钟运行，每轮最多扫描 100 个已开启通知的账号、投递 20 条。订单与工单扫描最近 48 小时事件，长期停机超过此窗口不补发历史通知。连续回复合并为当前最新一条，读取时与发送时均检查归属和资格。
- 发送前重新核对绑定和偏好；数据库唯一事件键去重。Telegram 429 按 retry_after 延后，403 停止该用户的通知；用户主动重新开启后恢复。网络超时、远端 5xx、发送后进程崩溃标记为结果不确定，不自动重发以免重复泄露信息或骚扰用户。
- 后台展示待发送、已发送、失败及结果不确定计数和最近 20 条异常。通知记录仅包含事件引用和状态，不保存正文；每分钟任务清理 30 天前记录，即使机器人已关闭也执行清理。不存在消息已读状态，也不宣称 Telegram 已送达等于用户已阅读。

部署须执行 `2026_10_13_000006_add_telegram_notifications.php`，`update.sh` 已包含该迁移。更新后重新设置 Webhook，以接收 `callback_query`。网站 API 没有新增敏感操作；通知设置通过验证来源且仅限私聊的机器人按钮更新，所有跳转仅使用管理员配置的 HTTPS 网站地址，不携带用户凭据。

本轮完成静态语法检查和前端构建后仍需使用专门测试账号进行真实 Bot 联调：新绑定默认关闭、通知类别开关、免打扰、解绑取消、续费取消旧提醒、屏蔽机器人、429、模糊发送结果，以及管理员/用户工单正文不会出现在通知中。
