# 独立流量额度与老用户迁移

## 使用规则

- 额度以 GB 展示，数据库按字节保存（1 GB = 1,073,741,824 字节），与账户现金余额及 Banked 重置次数相互独立。
- 有有效套餐时，先使用当前套餐配额，超出部分才扣额度。没有有效订阅也可使用额度。余额为零且无剩余有效套餐配额时停止访问；封禁始终优先。
- 额度无到期日，可累积。套餐续订、更换、自动重置、储备重置及管理员全局重置不会补回或清除额度；实际上传/下载和使用分析继续按真实报告记录。
- 后台「系统配置 → 订阅设置 → 额度基础权限组」配置后，有效订阅期间额度沿用订阅权限（套餐流量用尽也不降级）；订阅到期或无有效订阅时，额度仅可访问基础组节点。续费后自动恢复订阅权限。配置适用于所有额度，包括已迁移的旧一次性套餐；只改变运行时节点访问范围，不重写账户 group_id，不增减额度。限速和设备数继续采用账户已有设置。
- 基础组未配置时，保留此前沿用账户权限组的行为，避免升级立即中断现有用户。管理员应先将基础节点关联到所选权限组，再保存此项配置。基础组应仅含基础节点；同一节点若同时关联基础组与高级组，额度用户仍可访问该节点。
- 节点下次拉取用户列表时生效，客户端需更新订阅以刷新可见节点。到期后已缓存的高级节点不会继续获得节点端授权；正在进行的连接何时断开由节点软件刷新机制决定。变更无需新增数据库迁移，不会改变旧流量包的迁移识别条件。
- 后台原 `onetime_price` 显示为「额度包」，原流量字段为额度数量。只有上架且配置额度价格、正数流量和节点组的产品出现在额度选择器；正常套餐页面只展示有周期价格的产品。混合产品的周期价格与额度价格分别展示。
- 用户从「使用情况」或「账单」购买，选择规格后创建普通支付订单，仍支持现金余额抵扣及既有支付通道。结算金额由服务器计算，额度数量及首次访问配置在下单时留存快照，支付期间编辑产品不会改变购买数量。新订单类型为 5，周期保留 onetime_price 以兼容现有支付与返佣流程。

## 老用户迁移

迁移 `2026_10_02_000005_create_traffic_credits.php` 按旧后端的永久流量语义识别：有 plan_id、expired_at 为 NULL、transfer_enable > 0。包括历史一次性购买及管理员分配的永久流量。

每个用户在行锁事务内将 `max(transfer_enable - u - d, 0)` 转入 `credit_balance`，将原套餐配额置零，保留原 u/d、节点组、限速、设备限制、订阅 token/UUID、登录凭据和现金余额。用 `credit_migrated_at` 和唯一迁移记录防止重复增加。已耗尽用户不会获得额外流量。迁移可中断后重跑。

`v2_traffic_credit_log` 保存迁移前配额、用量与访问配置快照，以及每次到账的字节数、关联订单和产品快照。它记录额度来源；实际消耗仍来自原有流量报告，用户余额是当前可用值，不会由历史充值记录重新计算。

**升级前已创建、尚未完成的旧套餐订单**可能含旧套餐折抵金额。此类账户暂缓转换旧流量，避免既保留额度又获得现金折抵。取消旧订单后自动迁移；旧重置订单先兑现原有重置权益，再转换为额度；完成旧周期订单后沿用其已确认的换购规则；完成旧一次性订单则把最终应得流量转换为额度。订单开通加锁且检查状态，重复回调和队列重试不会重复到账。已取消和已完成的旧订单记录保留。

## 宝塔升级

此次不能只拉取静态文件。需要数据库迁移及同时升级流量统计、节点鉴权与支付队列代码。

1. 停止本站 Supervisor 队列、Horizon、计划任务，确认无在途处理；开启维护模式，并备份数据库、代码和 Redis 持久数据。
2. 使用新版 `update.sh`，提供真实、非空的数据库备份路径和 `--jobs-stopped`。脚本已定向执行此迁移，无需运行全部历史迁移。
3. 升级后核对迁移记录、额度余额、普通套餐用量、已完成/已取消订单及一个老一次性用户的配置导入。重启 PHP-FPM，再恢复本站队列、调度和访问。

手动执行该单项迁移的命令（仅在上述维护与备份条件满足后）：

```bash
/www/server/php/81/bin/php artisan migrate --path=database/migrations/2026_10_02_000005_create_traffic_credits.php --force
```

核对迁移来源总额（不是消耗后的当前余额）：

```sql
SELECT kind, COUNT(*) AS records, SUM(bytes) AS source_bytes
FROM v2_traffic_credit_log GROUP BY kind;
SELECT COUNT(*) AS deferred
FROM v2_user WHERE expired_at IS NULL AND plan_id IS NOT NULL
  AND transfer_enable > 0 AND credit_migrated_at IS NULL;
```

剩余 deferred 应逐个核对其旧待支付/开通中订单。已有用户无需重新登录或重新生成订阅链接。已下载的客户端可能仍显示旧额度/到期信息，刷新订阅后读取新的有效总量。

此次为余额语义迁移，**不能单独退回旧代码**：旧代码不识别额度、可能拒绝访问或错误计费。`down()` 主动拒绝删除余额，回滚须协调恢复升级前数据库、代码及相应 Redis 数据，并核对升级后交易。

## 精确重置时间

`user/getSubscribe` 新增 reset_at（Unix 秒）和 reset_timezone，保留 reset_day 兼容旧接口。日期按原 reset:traffic 的每日 00:00 调度计算，包含月末日期截断、到期前 25 天保护、每年规则和无重置模式；到期前没有下一次自动重置则返回 null。修复继承「每年首日」模式时意外继续执行「到期周年」分支的问题。

页面显示计划时间到分钟并标明后台时区。实际执行依赖计划任务健康，不把近似天数转换成假定时间。
