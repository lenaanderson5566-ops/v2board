# 用户管理按钮逐项核对

本轮范围为原后台 `/user` 用户管理页面，基准是 `public/assets/admin/res_005.js` 中的用户列表、筛选、行菜单和生成用户界面。新入口为 `/admin#/users`。下表区分实现验证与真实外部投递。

| 原按钮或控件 | 新界面行为 | 验证 |
| --- | --- | --- |
| 编辑 | 加载详情，编辑原有 19 个字段，保存后刷新 | 既有字段测试、后端保存回归；浏览器打开表单 |
| 分配订单 | 选择套餐后联动可用周期与金额，创建待支付订单 | 后端临时订单验证；无可用套餐时明确提示 |
| 复制订阅 URL | 复制列表返回的用户链接；失败时提供可手动复制的文本 | 浏览器点击及状态提示 |
| 重置 UUID/订阅 URL | 二次确认，替换 UUID 和 Token | 事务内临时账号验证，未重置现有账号 |
| TA 的订单 | 仅查询所选用户订单，支持分页与详情、佣金记录 | 后端筛选和详情验证；浏览器弹窗 |
| TA 的邀请 | 切换为邀请人 ID 筛选，显示全部匹配用户 | 浏览器切换及筛选接口 |
| TA 的流量记录 | 按用户查询记录，支持分页 | 后端临时流量记录；浏览器弹窗 |
| 删除 | 二次确认，删除用户及关联订单、邀请码和工单 | 事务内单个与批量删除回归，验证关联订单清理；未删除现有账号 |
| 导出 CSV | 下载全部筛选结果，正确返回 CSV 响应、设备数及转义单元格 | 下载客户端测试、后端 CSV 内容和范围验证 |
| 发送邮件 | 填写主题、HTML 正文，确认人数后加入群发队列 | 临时收件人、伪造队列验证，未真实发信 |
| 批量封禁 | 必须先筛选，确认范围和人数，注销匹配用户会话 | 临时账号验证，不影响其他用户 |
| 批量删除 | 必须先筛选，确认永久删除范围与人数 | 临时账号验证，不影响其他用户 |
| 高级筛选 | 原有 13 类筛选及设备限制；支持添加、删除、重置、应用 | 单元测试、后端嵌套参数验证；浏览器邮箱与状态组合 |
| 生成用户 | 指定前缀生成单个账号；留空批量生成 1–500 个并下载 CSV | 后端单个/批量生成与下载内容验证；浏览器表单 |
| 排序 | 原有 11 个排序字段、升序/降序 | 后端已用流量排序；浏览器选项 |
| 分页 | 每页 10/20/50/100/150、上一页/下一页 | 浏览器切换、后端分页 |
| 刷新 | 保持筛选、排序并重新获取列表 | 浏览器按钮 |
| 弹窗关闭 | 关闭筛选、编辑、订单、流量、生成和批量弹窗 | 浏览器逐个打开关闭 |

原来的右键菜单改为“更多操作”，同一组八项用户行操作分布在直接按钮及该菜单中。金额输入沿用当前后台的“分”，显示金额转换为“元”。用户订单弹窗提供查询与详情，支付/取消入口仍在订单管理页面。

批量操作覆盖全部匹配结果，不限当前页；封禁和删除不允许无条件操作。提交附带确认时人数，后端人数变化会返回 409，要求刷新并重新确认。该校验不构成数据库级快照锁定。

CSV 修复包括原接口直接 echo 导致响应格式不正确、批量生成未返回响应，以及 `devce_limit` 字段拼写错误；采用标准 CSV 引号转义、UTF-8 BOM 和公式单元格转义。包含账户初始密码的生成 CSV 应由操作者妥善保管。

验证结果：75 项前端测试、106 项后端冒烟检查通过，生产构建成功。后端测试使用事务回滚的临时账号/订单/流量数据，邮件队列被替换为测试实现，不产生真实邮件。SMTP 实际投递未验证。

其他模块的遗留差异仍列在 `admin-parity.html`，本报告不代表所有后台页面已经完全验收。
