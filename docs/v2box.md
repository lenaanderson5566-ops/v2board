# V2Box 节点接入

后台节点管理仅支持 V2Box，使用独立表 `v2_server_v2box`、V2Box 状态缓存及流量统计类型。模型、管理控制器、订阅、路由、部署、凭据、域名和额度绑定均统一为 `v2box`。

新安装直接创建 V2Box 表，不依赖旧表。历史迁移文件名为升级账本保留；V2Box 建表迁移使用独立结构。升级脚本执行 `2026_10_27_000001_retire_v2node.php`，删除旧 V2Node 配置表及其操作绑定、凭据和路由规则，保留 V2Box 数据和共享统计/账务历史。此清理不修改服务器上的服务或云资源。

Nodes 中配置 `"NodeType": "v2box"` 并填入后台 V2Box 的 `NodeID`；省略 NodeType 时也默认 V2Box。显式 `v2node` 将被拒绝，不映射到任何 V2Box 编号。安装器只接受 `--node-type v2box`。

通信沿用 `/api/v2/server/config` 与 `/api/v1/server/UniProxy/{user,alivelist,push,alive}`，参数为 `node_type=v2box`。管理接口沿用管理员前缀下的 `server/v2box/{save,update,copy,drop}`。用户订阅仍走 V10，按底层协议生成；原生节点稳定标识使用 `node_v2box_ID`。

V2Box 支持 Shadowsocks、VMess、VLESS、Trojan、TUIC、Hysteria2、AnyTLS、Naive。表单提供 TCP、WebSocket、gRPC、HTTPUpgrade；VLESS 支持 Reality。当前实现不接受 XHTTP、HTTP 传输、Xray VLESS 加密、可信 X-Forwarded-For、Proxy Protocol、ECH 等不兼容配置。高级传输参数也由后端检查。

## Naive

仅 V2Box 提供 Naive 协议，复用 `v2_server_v2box`，无需新增表或迁移。必须同步升级含 Naive 的 V2Box 二进制；旧二进制无法识别该协议。

- 管理后台选择 V2Box → Naive。首版仅 HTTPS/HTTP2：TCP + TLS；不支持 QUIC/HTTP3、Reality 或其他传输。
- 填写证书 SNI；证书模式选 HTTP/DNS 申请或已有文件，文件模式须填写证书和私钥路径。证书须被客户端信任并匹配 SNI；不提供面板生成自签名或跳过校验。
- 用户名与密码均使用订阅用户 UUID。支持用户热更新、账户撤销、流量计费和现有限速/设备限制；撤销时关闭该账户的 HTTP2 会话，其他账户不受影响。
- 订阅输出为 sing-box `type=naive`（需支持 Naive 的 1.13+ 客户端构建）和通用 `naive+https://` 链接；未适配的专用客户端格式跳过该协议。不能把通用链接支持理解为所有客户端均可用。
- 服务端不需要 libcronet；客户端可能需要。当前实现不包含 Naive 出站和网站回落/应用前置配置。

测试：`php tests/naive.php`、前端 admin-linkage 测试、节点 `GOEXPERIMENT=jsonv2 go test -race -tags with_quic,with_utls ./core -run Naive`。协议测试使用独立 HTTP2/Naive padding 测试客户端，覆盖实际 TLS 连接、流量计数、撤销/重加和并发更新；不替代目标 Chromium 客户端部署验收。

部署顺序：先发布包含 NodeType 支持的 V2Box Release，再升级面板并创建 V2Box 节点，最后使用后台安装命令部署。节点与面板须使用匹配的 V2Box 配置。

验证：`php tests/v2box.php`（仅本地环境，事务回滚测试数据），前端 `npm test -- src/admin/admin-linkage.test.ts src/shared/critical-config.test.ts`，节点仓库 `go test ./api/v2board ./conf`。

## 节点类型收敛

节点管理现仅保留 V2Box。旧独立 VMess、VLESS、Shadowsocks、Trojan、Hysteria、TUIC、AnyTLS 节点入口与后台 CRUD、旧节点通信已移除，旧记录不再进入订阅、排序、权限组节点计数及节点排行。底层协议仍可在 V2Box 中选择。升级迁移 `2026_10_11_000002_drop_retired_node_tables.php` 删除七张旧节点配置表及其中数据，不自动转换。共享账务、流量历史、权限组和路由表保留。升级前应把仍在使用的旧节点重新配置为 V2Box，并更新对应服务。删表无法通过回滚恢复数据，只能从数据库备份恢复。新安装不再创建这些表。

## V10 节点通信与 sing-box 原生配置

升级面板时执行完整 [update.sh 升级流程](update-script.md)（按批准清单定向迁移，勿执行全量 migrate），依次完成原生配置、独立路由和退役清理。新版 V2Box 配置 `NodeType=v2box` 默认走 V10，`ApiVersion=legacy` 可显式保留旧接口。V10 不接受查询参数 token，使用 Authorization Bearer；用户表为空时返回 `data: []`，304 才代表无变化。

管理端“路由管理”统一维护 V2Box / sing-box 规则。V2Box 原生规则在这里编辑 JSON，节点编辑页只选择当前内核可用的规则。开放 dns、route、outbounds，支持 HTTPS DNS、DNS 分流、inline/HTTPS remote 规则集及代理出口。保留直连出口 direct。不能覆盖入站用户、计费、服务、本机证书路径，也不能配置 auth_user 或本机 rule-set 文件。原生配置字段随节点固定的 sing-box 1.14.3 校验，错误配置先预检再重载。

节点通过 POST capabilities 上报 coreVersion 和 features，缓存 24 小时，随配置轮询更新；原生配置下发要求 X-Node-Capabilities 包含 native-routing-v1。节点能力不进入用户订阅。详细接口契约见 [node-api.json](api-v10/node-api.json)。旧节点通信仍调用相同的共享业务动作，流量上报暂未增加批次去重，202 仅表示已接受入队。

ACME 申请失败保护在节点本地实现，不通过面板清除；修复后按节点 README 恢复，重启不会绕过暂停状态。

V10 节点身份通过 `X-Node-Type: v2box` 和 `X-Node-ID: 节点编号` 请求头传递；URL 统一为 `/api/v10/server/...`。当前仅接受 v2box 类型。类型或编号缺失、非法时返回 422；未知节点返回 404。旧 `/api/v10/nodes/v2box/{id}/...` 路径已移除，面板与节点应同步升级。


## 独立路由规则升级

`2026_10_11_000004_separate_node_routes.php` 为路由记录增加 `backend` 和 `sing_box`。历史其他内核规则如仍被 V2Box 引用，先复制为 V2Box 记录并重新关联。新规则默认归 V2Box。节点内已有的原生配置迁移成一条 V2Box 路由记录，清空旧内联配置，并保持原生配置原先覆盖旧规则的行为。退役迁移随后清理旧内核规则。旧 `sing_box` 列暂留兼容数据库升级，但节点保存接口不再接受非空内联配置。

V2Box 可选择多条原生规则：`route.rules`、`dns.rules` 按选择顺序追加；相同定义的出口、DNS 和规则集标签复用，不同定义的同名标签及相互冲突的默认设置拒绝保存。旧格式兼容规则不能与原生规则混选，防止静默忽略旧规则。旧规则仍可独立编辑；转换为原生格式时，应同时检查使用该规则的节点。正在被节点引用的规则不能删除，须先解除选择。

节点通信格式不变：V10 的 `singBox` 返回所选原生规则的合并结果，`routes` 仅用于旧格式兼容规则。升级后配置 ETag 随规则内容变化。路由修改会同步影响选择该规则的节点，并在配置轮询时下发。

部署前备份数据库，执行完整 [update.sh 升级流程](update-script.md)（按批准清单定向迁移，勿执行全量 migrate），并发布新的后台资源。独立规则和引用不支持自动折叠回旧共享结构；需要回退时恢复数据库备份。验证：`php tests/node-routes.php`、`php tests/node-v10.php` 及前端 `Nodes.test.tsx`。


## 单一节点后端

仅支持 V2Box。节点编辑不再提供内核切换，保存接口拒绝 `source_type` 和 `source_id`。旧管理路由、模型、控制器、缓存键及安装入口均已移除；旧类型请求不会重定向或映射为 V2Box。

## AnyTLS 填充预设

AnyTLS 节点编辑可选“上游默认（推荐）”“低开销”“随机长度变体（实验性）”或自定义。默认预设下发空值，使用所选内核默认值；低开销仅处理前 4 个包，减少填充阶段；随机长度变体处理前 8 个包，改变尺寸区间。自定义内容会原样保留。预设只在 AnyTLS 显示，仍通过原有 `padding_scheme` / V10 `paddingScheme` 传递，无数据库迁移。

参数语义依据 [AnyTLS 协议说明](https://github.com/anytls/anytls-go/blob/main/docs/protocol.md)。减少填充会减少额外字节，也减少包长扰动；随机变体不是已验证的抗识别优化，不承诺更强的伪装效果或吞吐收益。真实线路需按延迟、流量开销和稳定性选择。预设源数据为 `resources/client/anytls-padding-presets.json`，已通过 V2Box AnyTLS 连接与业务流量计费测试。

## 公网 IP 查询与 Cloudflare DDNS

节点安装窗口提供公网 IPv4/IPv6 查询命令。查询在节点服务器执行，不会使用面板服务器或浏览器的 IP。后台“节点管理 → Cloudflare DDNS”统一管理凭据与节点绑定，支持 V2Box，默认不启用。

1. 执行完整 [update.sh 升级流程](update-script.md)（按批准清单定向迁移，勿执行全量 migrate），确保原有 Laravel scheduler 正常运行。
2. 后台新增凭据：名称、根域名、Cloudflare Zone ID、仅限该区域 DNS 编辑及 Zone 读取权限的 API Token。保存时验证域名与已激活的 Zone 一致。Token 使用 APP_KEY 加密保存，读取接口不返回原值，编辑留空保留旧值。备份/迁移面板时须保留 APP_KEY。
3. 新增节点后进入“部署与接入 → 域名与解析”，选择根域名、子域名前缀（留空自动生成）、IPv4 / IPv6 / 双栈。保存绑定暂不改变连接地址。
4. 新安装 V2Box：先保存域名，再生成一次性部署命令，复制到节点执行。脚本自动安装依赖、部署节点、配置独立 IP 上报，不需输入 Cloudflare Token。已有 V2Box 使用“配置 / 修复 IP 上报”生成一次性配置命令；改地址类型后也需重新配置上报。
5. 新安装会等待公网解析、启动证书申请并验证节点后自动启用域名，失败可按终端提示恢复。已有节点迁移仍在就绪后手动确认。同地址的直接子节点一并更新；证书名称、Reality SNI 或传输 Host 不随迁移替换。详细顺序、恢复与验证边界见 [自动证书部署](node-management-ui.md#自动证书部署2026-10-23)。

需 Python 3.8+ 和 systemd，或 OpenRC + crontab/crond。独立脚本支持两种节点程序：

```bash
python3 node-network.py ip
python3 node-network.py report-configure --family ipv4
node-network status
node-network disable
```

上报密钥通过隐藏输入读取，不进入 shell 命令历史；无交互场景可用 `--panel-url https://panel.example.com --token-file /root/node-report-key`。配置文件 `/etc/node-network/cloudflare.json` 使用 0600 权限，集中模式没有 Zone ID 和 Cloudflare Token。HTTPS 请求不跟随重定向，避免跨主机转发凭据。

节点每 5 分钟上报；面板调度器每分钟查找待同步记录，正常绑定约每 5 分钟校验 DNS。A、AAAA 分别记录新鲜度，超过 15 分钟不再使用该地址；部分地址查询失败不会更新另一地址的时间或删除已有 DNS。DNS 使用仅解析、TTL 300，只在内容或代理状态变化时写入；遇到多条同名同类型记录暂停，避免破坏多地址配置。

认证失败按凭据暂停所有关联节点；更换 Token 后恢复。配置错误暂停该绑定，修正后保存恢复。429 使用凭据级退避（Retry-After，5 分钟至 24 小时），上报或更换上报密钥不绕过该退避；临时网络失败延后重试，不在一次运行中循环请求。更换地址类型会撤销上报密钥，需重新配置脚本。切换节点内核自动迁移绑定；删除节点后拒绝上报和更新，并异步清理系统拥有且不再被引用的解析。旧版未托管记录不自动删除。

DDNS 日志默认保留 30 天，可在系统日志页面调整，由统一日志清理任务每 5 分钟分批处理；仅记录状态变化和 DNS 写入，支持节点筛选及分页；不会保存 Token、请求头或 Cloudflare 原始响应。系统日志不记录成功 IP 心跳，以免每 5 分钟重复落库。

旧版节点直接使用 Cloudflare 的 `configure` / 安装器 `--ddns` 模式保留兼容。推荐使用后台集中模式；执行 `report-configure` 验证成功后会替换原本地配置。若从其他独立 DDNS 程序迁移，应停止旧程序，防止双方争抢解析。首次改解析后等待 DNS 生效再申请 ACME 证书。

当前安装、升级及 IP 上报入口固定到已发布的 v1.0.3。基础域名托管复用该版本的辅助脚本；下述 TLS 域名验证切换需要另行发布并升级支持 `certificate-transition-v1` 的二进制。先完成面板定向迁移并确认 Laravel scheduler 正常运行。生命周期与迁移说明见 [节点管理](node-management-ui.md#cloudflare-节点域名闭环)。测试使用模拟 Cloudflare API，不会修改真实 DNS。

## 可选的节点访问目标统计

后台「日志设置」中的「统计用户访问的域名和 IP」默认关闭；报表入口为「访问与转化 → 节点访问目标」。仅管理员可读写。统计记录用户 ID、节点、原始目标域名或 IP、观察到流量的连接数及上下行字节，不包含 URL 路径、查询参数、内容或来源 IP。域名不做反向 DNS，IP 不被嗅探域名替换；客户端已自行解析的域名只能显示 IP。

面板和 V2Box 都需更新。面板沿用 update.sh，无新增迁移；节点必须部署包含 target-statistics-v1 能力的新二进制，并使用 V10 API。旧节点继续正常计费但不提供此统计。更新面板不会自动替换节点二进制。新节点通过独立任务同步开关，周期为 10–30 秒并增加最多 10% 错峰延迟，不占用计费上报任务，首次成功同步后开始采集；同步失败停止采集，授权最长 120 秒。关闭后面板立即拒收，节点下次同步停止，重新开启采用新版本并拒绝旧批次。

数据仅作运维参考：缓存保留约最近一小时，按接收时间的五分钟桶聚合，每节点每桶最多 500 个用户/目标组合，每页 25 条；不是历史审计库。节点最多保留 500 个待发送和 500 个当前组合，每会话最多识别 64 个目标。达到容量限制显示丢弃计数（采集操作数，并非独立访问人数）；重启、缓存丢失和网络异常可能丢失统计。固定批次 ID 去重，同 ID 内容改变拒收。节点重试批次最长保留五分钟，超时丢弃，避免超过面板去重窗口重复入账；丢弃计数还包括过期批次的记录数。统计请求总超时五秒、响应体最多 4 KiB。关闭后报表隐藏旧版本，旧缓存自然过期。

统计不参与套餐流量结算，连接数不等同网页访问次数。目标统计标签使用固定最近一小时窗口，上方天数筛选不适用。维护入口：TargetStatistics 服务、AdminTargetStatistics 页面，以及 V2Box core/target_statistics.go 和 node/target_statistics.go。


## 节点接入凭据与手动轮换

节点列表的「接入与凭据」为每个主节点生成独立凭据，绑定节点类型和 ID。凭据格式为随机标识加 32 字节随机密钥，面板仅存 SHA-256 摘要，明文只在生成响应中展示一次，响应禁止缓存。查询列表不返回明文或摘要。新密钥只接受 Authorization: Bearer；V10 继续拒绝查询参数认证。DDNS 上报密钥保持独立权限，不可混用。

所有生成、轮换、撤销及关闭全局认证操作均要求管理员权限和当前管理员密码，并受独立限流保护。记录创建人、创建时间、最近认证（最多每分钟更新一次）、失效时间、撤销时间及手动撤销人；撤销记录保留用于核对。普通请求日志只记录现有路由、状态等元数据，不写入密钥。未增加定时自动轮换。

首次迁移需安排人工切换：先升级支持独立 Bearer 密钥的节点，再生成凭据并立即写入节点。首次生成后，该节点立即拒绝全局 server_token，全部独立凭据撤销后也不会回退。父节点迁移后，其虚拟子节点也不能借全局密钥访问接口。已有独立凭据的手动轮换允许新旧密钥并行 30 分钟；宽限期内不允许再次轮换。新凭据认证后，后台点击「检查连接状态」核对指纹和最近认证，再手动撤销旧凭据；未操作时旧凭据到期失效，新密钥不会自动生成。若新密钥遗失，可撤销相关有效凭据后重新生成。紧急泄露应立即撤销，不等待宽限期。撤销阻止之后的面板认证，不终止已有代理连接。

V2Box 首次安装命令使用 --prompt-api-key，通过终端隐藏输入，不把密钥放入复制命令、URL 或 jq 参数。已有配置不会被安装器覆盖；升级节点后运行 `v2box credential`（需 python3），选择节点并隐藏输入新密钥，工具原子替换配置、设置 0600、不保存旧密钥备份，然后手动 `v2box restart`。多节点配置只修改选择项。命令不自动轮换或自动重启。

V2Box 的 legacy 模式已支持独立凭据通过认证头发送。节点安装列表不再返回含全局密钥的命令。

后台列出尚未迁移的主节点。全部主节点迁移且每个节点当前有效凭据至少认证成功一次后，才能关闭全局密钥认证；关闭后新节点也必须生成独立凭据，界面不提供恢复全局认证入口。删除节点撤销该节点全部凭据；转换内核撤销原凭据并保留禁止全局回退的状态，需要为新身份重新生成凭据。复制节点不会复制密钥。

升级使用 update.sh：新增 2026_10_20_000003_create_node_credentials.php 已纳入目标预检、迁移白名单和完成检查；新安装 SQL 也包含两张表。先更新面板和节点程序，再人工逐个迁移，不会因代码更新自动替换现有节点密钥。


## 节点 Release 与安装入口

节点程序、安装器、服务命令、IP/DDNS 和凭据工具随同一 Release 交付。当前面板代码的安装入口固定为 `v1.0.16`，实际升级应使用更新后后台生成的升级命令，先验收目标版本再安排维护窗口；不要将本节历史发布说明中的 `v1.0.1` 当作当前升级目标。后续发布新版本时同步核对面板入口和节点发布包。

以 root 在节点服务器执行后台生成的升级命令，再用 `v2box version` 核对版本。升级保留 `/etc/v2box/config.json`、证书、密钥及 IP 上报设置，无需再次提供密钥；运行中的节点程序会重启，停止的服务保持停止。

新节点从更新后的后台复制安装命令，按提示隐藏输入独立密钥。已有配置中每个节点的 ApiHost 必须为 HTTPS；不满足时在替换程序、重启服务前退出。安装器会验证发布包，失败按既有生命周期流程恢复原程序；配置、证书和部署状态保留。省略版本参数时查询 GitHub 最新正式 Release；固定版本便于先验收后部署。

发布工作流只在测试和六个平台构建全部成功后统一上传十二份安装包及校验文件；每个压缩包包含安装器、服务命令、IP/DDNS 和凭据工具。GitHub 标签 v1.0.0 的首轮发布检查发现 SS2022 Close 与首次响应写入竞态，因此未创建 Release；修复后使用 v1.0.1，不移动旧标签。SS2022 先中断底层 TCP I/O，再等待加密读写结束后释放缓冲区；不跳过竞态检查。


## 托管域名与 TLS 验证切换

管理后台保存或迁移根域名后，等待 IP 上报、Cloudflare 同步，再选择“验证并启用域名”。普通 TLS 节点同步连接域名、TLS SNI 和证书域名；同址 TLS 子节点同步证书身份及自签名指纹。Reality 仅更新连接域名，原 SNI、目标和密钥保持不变。未启用 TLS 的节点仍走直接域名启用流程。

待切换配置加密保存在绑定记录，最长有效 24 小时，不进入用户订阅。节点通过固定的 Cloudflare、Google 公有 DNS 查询确认 A/AAAA 与上报地址一致；最长等待两分钟，失败后保留旧监听。HTTP/DNS 模式按新域名独立目录申请证书，校验证书链、SAN、有效期、服务端用途与私钥配对；不会覆盖旧证书。自签名及远程证书校验身份并在成功后同步新指纹。文件模式要求已有证书覆盖新域名并提供受信任完整链，不替管理员签发或覆盖手动证书文件。

节点在停止旧监听前完成证书和用户配置准备。新监听启动失败，或面板拒绝确认切换时，恢复旧监听及本地用户和流量限制。面板只接受匹配当前候选、操作 ID 与配置哈希的成功回执；重复回执幂等，过期操作、配置已变更或缺少指纹不发布新地址。确认成功后，旧托管 DNS 至少保留 24 小时，仍被引用时不删除。旧证书文件保留用于恢复，不自动删除。

此流程会重建监听，既有连接可能断开，客户端需更新订阅以使用新域名/SNI/指纹；不是无中断迁移。网络故障造成确认响应丢失时，节点有限次重试；仍无法确认则恢复旧监听，后续配置拉取与面板的已提交状态重新一致。公有 DNS 或 CA 服务不可用时在后台检查状态和节点日志后重试，ACME 原有限流保护不被重试绕过。

部署必须同时升级面板和 V2Box：`update.sh` 已纳入 `2026_10_23_000002_node_tls_transition.php`，新安装 SQL 也包含候选字段。仅有 `configuration-receipt-v1` 的旧节点不支持此流程，后台会拒绝直接切换普通 TLS 域名。v1.0.4 引入该能力，v1.0.5 修复代理响应头导致的配置哈希错误；面板安装及升级入口统一固定到 v1.0.5。先更新面板、升级旧节点并等待能力上报，再启用目标域名。

出现 `invalid configuration hash` 时，v1.0.4 可能因配置 ETag 被弱化或移除，在新监听启动后无法提交回执而回退。新版面板在响应正文提供 `meta.configurationHash`，哈希仍只针对原配置数据，回执与候选发布校验不变；v1.0.5 优先读取该字段，兼容旧面板的强、弱 ETag。缺失或无效版本在准备证书及停止旧监听前拒绝，不缓存失败响应。升级后仍有效的候选会再次处理；已超时或被撤回时，在后台重新验证。不要通过关闭证书验证或直接改订阅地址绕过此流程。

后台路由管理不再显示适用内核列或内核选择控件，新建规则只接受 sing-box 原生格式，已有 V2Box 兼容格式规则仍可编辑。节点编辑元数据与保存接口共用明确的验证规则；后台不解析控制器源码，也不向表单提供旧内核专有字段。类型字段仍用于接口身份校验，拒绝将退役类型映射到同号 V2Box 节点。

原生路由模板与当前固定的 sing-box 1.14.3 对齐，提供域名阻断、IP/CIDR 阻断、域名代理出口、HTTPS DNS 分流及远程 HTTPS 规则集。模板中的示例域名、服务器和 URL 必须按需修改；选择模板会替换编辑器内容。列表展示配置摘要和引用服务数。配置片段按节点选择顺序合并后验证出口、DNS、规则集和域名解析器引用，允许跨片段引用，拒绝未定义标签、重复冲突和已退役的 geoip/geosite 匹配；后者应改用 rule_set。模板由面板共享 JSON 提供，节点仓库保存测试快照并通过实际核心配置解析回归。

V10 与兼容通信接口共用 `NodeConfiguration` 的路由解析结果：分别通过 `singBox`、`sing_box` 原样传递原生配置，兼容接口同样支持原生路由，不再只返回旧格式规则。规则编辑会改变配置版本；兼容接口正确处理 V2Box 回传的带引号 ETag，不变配置返回 304。仅更新路由时节点仍触发重载，加载失败沿用既有重试/回滚流程。此修复随面板更新生效，未新增节点核心功能或自动发布二进制。


## 在线统计与有效上报窗口

在线上报是每个节点的完整观察快照。合法空快照、用户未出现在下一次快照中，都会清除该节点的旧记录；其他节点的记录独立保留。非法 JSON 不作为空快照处理。升级后首次上报前没有节点索引的旧缓存自然过期，不通过扫描 Redis 全库补建索引。

所有设备计数、个人订阅、后台用户列表和风控在线列表共用 OnlineDeviceService 的有效性与去重规则，不使用存储的旧聚合值或额外缓存的 ALIVE_LIST。默认上报间隔 60 秒时，有效窗口为 100 秒；窗口取 max(100, ceil(1.1 × 上报间隔) + 30) 秒，间隔按 1～86400 秒保护性限制，缓存另保留 20 秒清理余量。间隔 300 秒时窗口为 360 秒。窗口内仍可能存在采样延迟，不能解释为实时连接数。

严格模式按各节点的唯一来源 IP 数求和；宽松模式在节点之间继续去重。IPv6 的等价写法以及 IPv4 映射 IPv6 归一化，同节点重复 IP 不重复计数。节点的设备在线流量阈值按用户在本周期的总流量判断，IP 数不能精确表示物理设备数：共享出口、多地址及多节点连接都会影响估算。

仪表盘“近 10 分钟活跃用户”继续按计费活动统计；节点的“服务活跃用户”是最近流量上报周期的活跃人数，共享线路不能相加。风控“在线用户”按有效在线快照查找，不再要求用户近期必须产生计费流量；最近活跃显示实际节点上报时间。历史最近连接记录仍保留，下线不会抹除历史。

节点完整修复需要同时更新面板代码和节点二进制：节点在观察集为空、或全部未达到设备阈值时也上报空快照，取消流量请求不会提前丢弃在线采样。仅更新面板静态资源不能改变已运行节点的行为。本轮不修改数据库结构、API 路径或发布版本，不自动更新、重启真实节点。
